## 단계 카드 브리핑 스택과 서비스 지도 타일 (2026-11-21 인터뷰)

`docs/plans/stage-card-brief-2026-11-21.md`가 범위·완료 기준·검증을 기록한다. 이 절은 아래 **공통 관제 카드의 오른쪽 카드 구성(둘째 문단)**과 P21의 **지도 노드·환경 칩 모양**을 대체한다.

- 단계 카드는 12개 단계 모두 같은 순서다: 머리(단계명 · 상태 톤 배지 · 우측 상단 모델 태그) → 결정(승인·종결 카드만) → 이어받음 → 브리프 → 데이터.
  - 모델 태그는 그 카드에서 실제 호출한 `모델 · 추론 강도`를 중복 없이 보인다. 판단 기록의 각 행에도 같은 태그를 단다.
  - 상태 배지는 톤을 가진다: 실행·대기 = accent, 사람 대기·승격 = warning, 완료 = success, 실패 = danger, 그 밖 = muted.
  - 이어받음은 이 단계로 들어온 흐름도 연결선과 앞 단계의 첫 줄을 한 줄로 보인다(최대 2줄, 넘치면 `외 N`). 누르면 그 단계를 연다. 뒤 단계에서 되돌아온 선은 반려·경로 변경·운영자 지시일 때만 쓴다(`독립 검증 반려 → 재조사`).
  - 브리프는 회색 판 하나다: 진행 중(작업 중일 때만, 역할·진행 단계) → 첫 줄 결론(`.step-lead` 정확히 1개, 16px/600) → 사실(`dl.stage-facts`) → 목표 점검 → 남은 것.
  - 카드군별 첫 줄과 사실: 관측 카드는 최초 → 최근 변화, 분석 카드는 결론과 신뢰도·근거 구성, 수정·QA 카드는 같은 시험의 수정 전 → 후, 승인·종결 카드는 결정과 보류 사유를 맨 위에 둔다.
  - 원인 조사 목표 점검은 백엔드 차단 규칙과 같다(신뢰도 80% 이상, 부족한 근거 0건, 인용이 수집 근거와 일치, 반론·심층 검토). 상태 점은 충족(success) · 미충족(danger) · 진행 중(accent 점선) · 확인 전(muted)이다.
  - 데이터는 건수가 달린 펼침 행(button, 44px, `aria-expanded`)이다: 판단 기록(역할별 한 줄 요약 · 시각 · 모델), 근거, 원문·기록. 실행 중인 호출과 그 판단 기록은 열린 채 시작해 답변이 끝나도 닫히지 않는다.
  - 근거는 출처 종류별로 묶고 같은 출처(ref)는 한 행에 `인용 N`과 인용한 역할로 합친다. 원시 ref(`source:…`)와 발췌는 행을 펼쳐야 보인다. Application 소스 코드 인용은 해석 모델에 보내지 않고 `파일 · 인용 N · 역할`로만 설명한다.
- 한글 정리 표시: 표시 가능한 한국어는 그대로, 정리 중은 `정리 중`, 새 정리 도입 이전 기록은 `과거 데이터 없음`, 새 데이터의 정리 실패나 표시 필터에 걸린 문장은 생략한다. `한글 해석 실패·미관측·미기록` 같은 해석 상태 문구는 어디에도 쓰지 않는다. 사실 미관측(자동 QA 미관측, 시각 미관측 등)은 그대로 둔다.
- 판단 기록에는 단계의 실행 단위(분석·분류·검증·추가 조사)가 모델 기록이 없어도 모두 한 행씩 들어간다. `전달한 요청`은 호출 ID로 이어지는 요청 기록이 있을 때만 보이고, 결과에서 요청을 거꾸로 만들지 않는다.
- 관제실 머리의 `다음` 줄은 늘 보이고, 결정이 필요할 때만 `지금 할 일` 띠와 이동 버튼이 된다(아래 P18 규칙과 같다). dev 사용자 시험을 기다리는 Application 사건은 dev 검증 카드 맨 위에 그 결정(`dev 사용자 시험 기록`)을 둔다.
- 수집 진단의 `인프라 연결 지도`는 오른쪽 칸 안에서 높이 360px를 가지며 다크 위상 지도(#11181c)로 그린다. 선택한 자원의 바탕은 `#b9c8da` 10% 혼합으로, 모든 다이어그램 글자 색이 4.5:1 이상을 유지한다.
- 서비스 지도 노드는 상태 점 타일(시안 C)이다. 타일 폭은 176px로 고정해 레인을 따라 늘어나지 않는다(600px 이하는 두 열). 준비 상태 칩은 `dev ●`처럼 점만 보이고 낱말은 화면 낭독기·도움말에 남긴다. 장애·주의·미관측일 때만 글자와 톤(배경색, 미관측 점선)을 보이고, 경고 아이콘은 장애·주의 타일에만 둔다.

## P21 서비스 지도 재구성과 naria 전체 정리 (2026-11-21)

`docs/plans/revamp/P21-service-map-naria.md`가 범위·결정·검증을 기록한다. 이 절은 아래 계약 중 **운영 관제 › 서비스 지도의 배치와 시각 규칙, 공용 구성요소의 치수·색**을 대체한다. 동작 계약(사건 진입, 선택 상세, 수집 진단, 미관측 ≠ 0, 이관 이력 분리, 접근성)은 유지한다.

- 서비스 지도는 시안 B(시스템 레인)다. 시스템은 가로 레인(왼쪽 이름·요약, 오른쪽 노드 열), 레인 사이는 1px 구분선만 둔다. 카드 안에 카드를 겹치지 않는다.
- 레인 순서는 연결로만 정한다. 연결된 시스템을 붙이고 가장 많이 호출되는 시스템을 호출하는 시스템 사이에 두며, 연결된 서비스를 레인 앞에 둔다. 상태(장애·주의)로 위치를 바꾸지 않는다.
- 노드는 naria DiagramNode 규격(경계, control 곡률, `--nds-shadow`, 28px 아이콘 칸)이다. 환경 칩은 naria `StatusIndicator`이며 장애·오류(danger) · 주의(warning) · 준비(ok) · 미관측(속 빈 점선 점)을 문구와 함께 보인다. 칩은 `장애 3`처럼 짧게 쓰고 읽기 이름은 `장애 3건`을 유지한다. 노드 설명 줄은 두 환경 합계(`장애 4건`, 장애색)와 연결(`→ 대상 · 선언`, 보조색)을 함께 쓴다. 사건이 있어도 준비된 Pod의 관측 문구는 `준비`다.
- 연결선은 노드 사이 빈칸으로만 지난다(관측 실선, 선언 점선, 도착 쪽 화살표). 600px 이하 한 열에서는 선 대신 노드의 `→ 대상 · 선언` 문구를 남긴다.
- 지도 아래 독립 행에 naria `ZoomControls`(80–160%, 전체 보기)와 상태·연결선 범례를 둔다. 수집원이 모두 연결되면 머리에 버튼 하나만 두고, 문제가 있는 수집원만 따로 보인다.
- 데스크톱(840px 초과)은 페이지가 스크롤되지 않는다. 지도와 오른쪽 운영자 개입이 각자 영역에서만 스크롤한다. 높이 860px 이하에서는 레인 여백을 8px로 줄여 1280×800에서도 실데이터 서비스 14개가 잘림 없이 보인다.
- 색·글자·곡률·간격은 naria 토큰만 쓴다: 의미 색은 `var(--nds-*)`, 굵기 400/600, 글자 12·13·14·16·18·24px(배지 11), 곡률 6·10·16·24·pill(메뉴·태그 8, 알림·표 12, 토스트 13은 naria 구성요소 고유값), 간격은 4px 기반 척도와 naria 구성요소 규격값. 다크 다이어그램은 naria 다크 토큰 값(배경 #11181c, 묶음 #20292d, 노드 #303b40, 경계 #707d83, 본문 #f6f8f8, 보조 #b6c0c4, 강조 #b9c8da, 완료 #89dcb0, 경고 #f3ca68, 실패 #ff9da6, 경로 변경 #80d9cc)이다. 관제실의 밝은 흐름도는 naria 밝은 토큰을 쓴다.
- 공용 클래스(`btn`, `badge`, `input`, `select`, `card`, `table`, 보기 전환 탭, 빠른 필터, 메뉴, 상단 바, 알림 메뉴, 토스트, 안내·오류 상자)는 `naria.css`의 P21 블록에서 naria Button(sm 36px · 입력 옆 md)·Badge·Input(16px)·Card(outline, 22px)·DataTable·Tabs·Tag·SideNavigation(190px, 항목 44px)·Alert·Toast 규격을 따른다. 터치 입력에서는 작은 버튼·태그도 44px이다. 포커스는 2px 외곽선, 간격 3px이다.
- 독립 Application 관제 화면(`liveprobe/app/application/static`)도 같은 naria 토큰 값을 `:root`에 정의해 쓴다. 이 화면은 Wanted Sans 파일을 따로 싣지 않으므로 글꼴 스택의 다음 글꼴로 표시될 수 있다.
- naria 2차 정리 규칙(엄격 검증 기준):
  - 옛 변수(`--line`·`--text-2`·`--accent`·`--danger`·`--font`·`--mono` 등)는 `naria.css` 맨 앞 블록에서 `.nds-theme` 안의 naria 토큰으로 다시 정의한다. `:root`의 같은 이름 값은 테마 밖 `body` 기본값일 뿐이다.
  - 글자 간격은 글자 크기의 naria 값을 쓴다. 12·14·16px은 0(`--nds-type-caption|small|body-tracking`), 18px은 −0.015em, 24px은 −0.025em(`--nds-type-heading-tracking` −0.6px), Card 제목 17px은 −0.02em이다.
  - 줄 높이는 naria 어휘(1 · 1.18 · 1.3 · 1.4 · 1.5 · 1.6 · 1.65 · 1.7)나 type 토큰만 쓰고 px 값은 쓰지 않는다. 테마 기본은 14px/1.65이고, 단계 번호처럼 옆 줄과 맞춰야 할 때는 `calc(var(--nds-type-small-size) * var(--nds-type-small-line))`을 쓴다.
  - 위치 오프셋도 간격 척도를 따른다(예: 배지 −12px·−16px).
  - 버튼은 naria Button sm 36 · md 44 · lg 52, 탭은 46(`.nds-tablist`), 태그·필터 칩은 32(`.nds-tag`), 입력은 컨트롤 높이(44), 대화 입력창은 naria composer(컨트롤 높이 · 10px 14px · 1.5), 체크박스는 20(`.nds-check-mark`)이다.
  - primary hover는 `filter: brightness(0.92)`이다. 고리 그림자는 naria 모양(후광 `0 0 0 3px`, 맥박 45% → 7px, 1.6s)을 쓴다.
  - 흰색은 `#fff`·`white` 대신 `--nds-surface`(배경)·`--nds-on-primary`(색 위 글자)로 쓴다. 다이어그램 연결선·격자 색은 naria 토큰 값이다(밝은 흐름도는 라이트, 위상 지도는 다크, modern 팔레트 계산값 포함).
  - 클래스 없는 기본 `input`·`select`·`textarea`·`button`도 브라우저 기본 모양으로 두지 않는다. naria Field(세로·간격 8px)·Label(13px/600)·Input(컨트롤 높이·11px 13px·16px·strong-border)·Select·Textarea(110px) 규격으로 그리고, `scan-native.cjs`로 실화면에서 0건을 확인한다.
  - 검증: `docs/evidence/P21-service-map-naria/naria/naria-verify.py`가 모든 색·간격·위치·곡률·글자 크기·굵기·글자 간격·줄 높이·컨트롤 높이와 TS 색을 naria 토큰이나 naria 구성요소 CSS의 같은 속성·값 줄과 대조한다. 근거 없는 값은 0건이어야 한다.

## P20 naria 디자인 시스템 리뉴얼 (1차 · 구현, 실배포 검증 전)

`docs/plans/revamp/P20-naria-renewal.md`가 범위와 판단을 기록한다. 이 절은 아래 계약 중 **색·서체·곡률과 운영 관제 상단, 장애 목록 필터**를 대체한다. 그 밖의 동작 계약(스크롤 정책, 확인 경계, 접근성, 다이어그램 구조)은 유지한다.

- 색·서체·곡률의 기준은 `@naria/ui` 토큰이다. `src/naria.css`가 `styles.css`의 변수(`--text`, `--accent`, `--line` …)를 `--nds-*` 토큰에 연결하고, `src/room.css`가 관제실 내부의 형태를 정한다. 아래 표의 예전 색 값은 이력이다.
- **서체 규칙(2026-11-14 변경): 번들에 내장한 서체를 쓸 수 있다.** 현재 서체는 디자인 시스템 CSS에 내장된 Wanted Sans 400/600이다. 실행 중 외부 글꼴 서버로 요청을 보내지 않는다는 조건은 유지한다. 이전의 "웹 폰트 없음"·"시스템 글꼴 스택 유지" 규칙은 이 규칙으로 대체한다.
- **디자인 시스템과의 관계: 디자인 시스템은 초기 세팅용이다.** `vendor/naria-ui-1.0.1.tgz`는 시작 시점의 사본이며, 이후 이 대시보드의 토큰 연결·컴포넌트 형태·화면 스타일은 대시보드가 스스로 바꾼다. 디자인 시스템 저장소와 계속 맞출 의무는 없다.
- 다이어그램 작업면은 디자인 시스템 다크 토큰 값을 쓴다: 배경 `#11181c`, 묶음 `#182126`, 노드 `#20292d`, 선택 `#2b3a44`, 경계 `#4a585f`, 본문 `#f6f8f8`, 보조 `#c9d2d6`, 메타 `#b6c0c4`, 선택·실행 `#b9c8da`, 완료 `#89dcb0`, 경고 `#f3ca68`, 실패 `#ff9da6`. 보라색은 쓰지 않으며 경로 변경·이벤트 연결은 청록 `#80d9cc`다.
- 운영자 우선순위: 운영자 결정이 없으면 멈추는 상태(조치 승인 대기, 미인수 인계)가 알림·대기열·목록에서 항상 먼저 온다. 그다음이 조치 중, 분석 중이며 같은 상태에서는 수준 높은 순이다(`src/responseQueue.ts`).
- 운영 관제 상단은 **지금 대응할 일**이다: 상황 문장(`role=status`), `승인 대기 / 미인수 이관 / 진행 중` 집계, 대응 순서의 장애 카드 최대 4개와 전체 목록 링크. 집계는 서버 `counts`를 우선하고, 없으면 완전히 조회된 실시간 목록에서만 세며, 그것도 없으면 `미관측`이다. 미인수 이관은 추정하지 않는다.
- 장애 목록의 빠른 필터는 `전체 · 대응 중(승인 대기/운영자 이관/분석 중) · 처리 결과(자동 복구/운영자 종료/처리 실패)`다. 운영자 결정이 필요한 장애가 있으면 목록 위에 바로가기 띠를 둔다.
- 관제실 상황 요약의 `다음` 줄은 결정이 필요한 상태에서 `지금 할 일` 띠가 되고, 버튼으로 결정 카드(승인·인계)까지 이동·포커스한다. 움직임 감소 설정에서는 즉시 이동한다.
- 관제실 내부(2차): 대화 영역은 옅은 회색 바탕 위에 흰 카드를 놓는다. 단계 카드는 왼쪽 색 띠 대신 **제목 앞 상태 점 + 상태 배지**로 상태를 알리고(완료 녹색, 실행 중 강조색 맥동, 실패 적색, 승격 주황, 예정·건너뜀 점선), 실행 중 카드는 강조색 테두리와 고리를 갖는다. `펼치기`·`원문 보기`는 카드 머리 오른쪽의 보조 버튼이며 480px 이하에서는 카드 아래로 내려간다.
- 결정 카드(승인·인계)는 흰 표면에 경고색 머리 띠를 두고, 종료 카드는 중립 머리 띠를 쓴다. 운영자 지시 카드는 번호가 붙은 작업 목록, 사전 검사, 경고색 부작용 상자, 확인 영역 순서다. 운영자 말풍선은 오른쪽 강조 연한색, AI 해석은 왼쪽 중립 표면이다. 원문·로그는 고정폭 12px의 옅은 회색 상자다.
- 흐름 노드의 연결 문구 바탕과 캔버스 배경은 `#11181c`다.
- 관제실 설명 요소(3차): 그룹 카드는 **접힌 상태에서도** 역할별 모델·추론 강도를 보인다(이전 계약 "역할 구성은 상세에서만"을 대체). 수준 판단 카드는 주 분석 모델과 선택 이유를 접힌 상태에서, 후보 점수 표를 펼친 상태에서 보인다. 분석 카드는 원인 후보·근거 인용 요약·반대 근거·참고 문서를, 검증 카드는 판정과 후보별 수락 여부를 보인다. 승격된 단계와 재실행 단계에는 승격 사유가 붙는다. 상황 요약에는 AI 사용 요약(호출 수·모델별 호출·토큰·비용·응답 시간 합)이 있고, 값이 하나라도 없으면 합계는 `미관측`이다.
- 원문 규칙은 유지한다: 인용문, 영문 사유, 영문 반대 근거, 문서 발췌는 요청(펼침)할 때만 DOM에 넣는다. 서버가 새 필드를 보내지 않으면 해당 영역을 그리지 않는다.
- 메뉴 아이콘은 Radix Icons, 상태 점·미터·배지는 `@naria/ui`의 `StatusIndicator`·`Meter`·`Badge`다. 실행 의존성은 `@naria/ui`와 `@radix-ui/react-icons`가 늘었다.

## P16 다이어그램 시각 계약

기본 방향은 **정밀한 운영 콘솔**이다. 두 다이어그램만 짙은 흑연색 작업면으로 분리하고 기존 밝은 메뉴·근거·대화 영역은 유지한다. 장식성 그라디언트·유리 효과·대형 제목·새 라이브러리는 추가하지 않는다. Linear의 명도 단계·절제된 테두리와 로컬 디자인 자료의 Slate Console을 참고하되 브랜드·서체를 복제하지 않는다. 기존 흰 카드의 균일한 녹색 테두리, 의미 없는 문자 아이콘, 작은 원천 수치의 반복을 개선한다.

- 배경 `#0c1420`, 네임스페이스 표면 `#111d2d`, 노드 `#19283b`, 선택 노드 `#213452`, 경계 `#34465f`, 점 격자 `#28384d`.
- 본문 `#edf3fc`, 보조 `#b7c6d9`, 메타 `#a0b2ca`, 선택·실행 `#a9baff`, 완료 `#85dfb5`, 승격·경고 `#ffd08a`, 실패 `#ff9da7`, 재배치 `#d0b1ff`. 밝은 화면의 기존 토큰은 유지한다. 새 색은 다이어그램 범위에만 적용한다. 텍스트 대비 4.5:1 이상.
- 한국어 글꼴은 내장 서체(P20 서체 규칙), 수치·모델 식별자는 고정폭 스택. 다이어그램 주요 제목 14–15px, 설명 14px, 수치 메타 12px 이상(확대 전 좌표 기준). 축소 전체 보기에서는 확대 제어로 원래 크기를 읽을 수 있게 한다. 모델·긴 이름은 상세와 접근 이름에 원문을 보존한다.
- 서명 요소: 역할별 선형 SVG 아이콘, 단계 번호와 실행 상태의 분리, 네임스페이스 상단의 자원 수·문제 수, 실측 연결의 두께·상태와 미관측 점선. 모든 상태는 색과 문구를 함께 사용한다. 완료 단계 전체를 녹색 상자로 채우지 않는다.
- 간격 4/8/12/16/24px, 노드 반경 10px, 묶음 반경 14px, 미세한 노드 그림자만 허용한다. 선택은 밝은 테두리+외곽선, 키보드 포커스는 별도 3px 외곽선이다. 호버는 경계 밝기만 바꾸며 노드 위치는 움직이지 않는다.
- 서비스 지도: 전체 자원/네임스페이스/실측 연결 개수의 짧은 요약, 기존 필터·전체 보기·장애 진입·모든 상세 수치를 유지한다. 신규 건강 점수·가상 트래픽은 만들지 않는다. 미관측은 정상으로 표현하지 않는다.
- 실시간 연결 관측으로 같은 자원 수에서도 열·행·묶음 배치가 달라질 수 있다. 자원 개수가 아니라 실제 노드/묶음의 식별자·위치·크기가 바뀔 때 전체 맞춤을 다시 수행한다. 수치만 갱신되면 운영자의 확대·이동은 유지한다.
- AI 흐름: 위→아래 depth·좌→우 lane·병렬·승격·운영자 지시 경로를 유지한다. 종류 아이콘과 작은 단계 번호로 경로를 읽고 상태 배지는 별도 표시한다. 단계 선택·결론·근거 이동은 기존 API 그대로다. 전체 맞춤의 최소 읽기 배율 정책을 유지한다.
- 범례와 확대 제어는 캔버스 아래 독립 행이다. 1440/768/375px에서 제어가 노드를 가리지 않고 페이지·패널 가로 넘침이 없어야 한다. 빈 흐름·미관측 지도·오류·지연 경고에도 동일한 시각 위계를 유지한다.
- 움직임은 실행 중 연결만 사용하며 기존 움직임 감소 설정에서 끈다. 배경의 가짜 실시간 점멸·무의미한 맥동은 추가하지 않는다.
- 성능 예산: 로컬 Chromium 1440×900, 네트워크·CPU 제한 없는 새 페이지의 `/`·`/incidents/1019`에서 실험실 LCP 2.5초 미만. 구현 전 동일 조건 기준선을 기록한다. 실제 사용자 p75·INP 통과 주장으로 확대하지 않는다.
- 변경 범위: 두 다이어그램·공유 확대 제어·전용 스타일·회귀시험·대시보드 배포. 백엔드·실행 권한·인증·클러스터 자원 구성·평가 화면·Jira·커밋·push는 제외한다. 아래 P15 동작 계약은 이 절에서 변경한 시각 규칙 외에는 유지한다.

## 목적과 화면 구조

첫 화면은 클러스터 전체의 **운영 관제**다. 주인공은 **서비스 연결 지도**다. 지도에서 장애 위치를 찾고, 장애 자원을 누르면 그 장애의 **장애 관제실**로 이동한다. 장애 관제실은 단순한 인계 배지가 아니라 AI가 거친 단계를 위에서 아래로 보여 주고, 각 단계의 한글 결론과 근거, 운영자가 할 다음 일을 드러낸다.

- `/`: 서비스 연결 지도(왼쪽 전체) + 클러스터 상태 보조 영역(오른쪽).
- `/incidents`: 검색·상태 필터·현재 AI 단계가 있는 장애 목록.
- `/incidents/:id`: 한글 상황 요약 + 세로 분석 흐름 / 단계·근거 / 운영자 대화.
- `/ledger`, `/settings`: 검토 기록과 버전형 모델 설정을 유지한다.
- `/map`: `/`로 이동한다. Kiali 삽입 화면과 이전 자원 지도는 사용하지 않는다.
- 메뉴: 운영 관제 / 장애 관제 / 검토 기록 / 설정. 작은 화면: 관제 / 장애 / 검토 / 설정.
- 상단 바: 왼쪽은 현재 위치(예: 장애 관제 / 장애 #971), 오른쪽은 분석 계정 상태와 **진행 중 장애 알림 버튼**이다.

## 시각 원칙

밝은 상용 관측 콘솔의 정보 밀도와 위계를 따른다. 흰 작업 표면, 옅은 회색 배경, 얇은 구분선, 작은 상태 색을 사용한다. 장식형 히어로·그라디언트·차트 라이브러리는 추가하지 않는다. 화면 제목만 있는 머리 영역은 두지 않는다(보조 기술용 제목은 유지한다). 수치는 원천 값이며 임의의 건강 점수를 만들지 않는다.

색 토큰은 `styles.css`가 기준이다.

| 역할 | 전경 | 배경 |
| --- | --- | --- |
| 본문 | `#172337` | `#ffffff` |
| 보조 설명 | `#526174` | `#ffffff` |
| 메타 정보 | `#607086` | `#ffffff` |
| 선택·포커스 | `#245bb5` | `#edf3ff` |
| 준비·완료 | `#126840` | `#eaf6ef` |
| 경고·인계 | `#934807` | `#fff3e2` |
| 오류·장애 핀 | `#b4232c` | `#fff0f1` |

본문과 상태 텍스트는 해당 바탕에서 명도 대비 4.5:1 이상을 확보한다. 색만으로 구별하지 않고 상태 문구와 경계선 형태를 함께 사용한다. 포커스는 3px 외곽선이다.

서체는 번들에 내장한 Wanted Sans이며(P20 서체 규칙) 대체 글꼴은 시스템 스택이다. 실행 중 외부 글꼴 서버에서 내려받지 않는다. 일반 본문 14px, 한글 해석 13px, 관제실 설명 12px, 조밀한 메타 10–11px다. 원문·모델 ID·근거 ID는 시스템 고정폭 글꼴을 사용한다. 한국어는 어절 단위 줄바꿈을 우선하되 긴 이름과 원문은 영역 안에서 줄바꿈한다. 흐름 노드의 둘째 줄(종류·모델·내용)만 한 줄 말줄임을 허용하며, 전체 문구는 접근 이름과 단계 상세에 남긴다.

간격은 4/8/12/16/18/24px, 모서리는 4/6/8/10px다. 그림자는 지도 자원, 흐름 노드, 알림 드롭다운에만 작게 사용한다.

## 스크롤 정책

데스크톱(1100px 초과)에서는 **페이지 자체가 세로로 스크롤되지 않는다**. 남는 스크롤은 아래 네 가지뿐이며 각각 목적이 있다.

1. 장애 관제실 가운데 열: 근거 묶음과 선택 단계 상세 열람.
2. 장애 관제실 오른쪽 열: 대화·실행 기록·지시 카드 열람. 입력란은 열 하단에 고정된다.
3. 운영 관제 보조 영역의 탭 내용: 경고 이벤트 / 네임스페이스 / 자원 상세.
4. 알림 드롭다운의 장애 목록(장애가 많을 때만).

지도와 흐름은 스크롤 대신 확대·축소·전체 보기와 끌어 이동을 사용한다. 1100px 이하에서는 탭 전환과 세로 쌓기를 허용하고, 운영 관제는 지도(화면 높이의 약 2/3) 아래에 보조 영역을 둔다.

## 운영 관제

**지도**가 왼쪽 전체 높이를 차지한다. 도구 줄에는 제목, 네임스페이스 선택, 자원 선택(지도에서 숨긴 자원 포함), 시스템 구성요소 표시 전환, 자원 수가 있다. 처음 열거나 보이는 자원 구성이 바뀌거나 캔버스 크기가 바뀌면 **전체 지도를 화면에 맞춘다**. 일반 10초 갱신은 운영자가 옮긴 시점을 유지한다.

- 네임스페이스 경계 안에 진입 → 서비스 → 저장소 계층을 배치한다. 각 네임스페이스 상자는 **실제로 쓰는 열만** 차지하고, 상자들은 화면 비율(가로 1.25:1)에 가깝게 여러 줄로 배치한다.
- **시스템 구성요소**(kube-system, kube-public, kube-node-lease, liveprobe-observability, istio-system, default/kubernetes, system·job 역할)는 기본으로 숨긴다. 문제나 열린 장애가 있는 구성요소는 숨기지 않는다. "시스템 구성요소 N개 표시"로 모두 보이고, 특정 네임스페이스를 고르면 그 안의 자원을 모두 보인다. 숨김은 화면 정리일 뿐이며 자원 선택 목록에는 "지도에서 숨김"으로 남는다.
- 접힌 Service의 이름·포트·준비된 엔드포인트 수를 상세에 보존한다. 엔드포인트가 0개인 Service는 '엔드포인트 없음' 경고이며 시스템 네임스페이스여도 숨기지 않는다. 간선은 상대 노드와 마주 보는 면에 붙인다. 선 위 숫자는 관측된 요청률이 있으면 `초당 요청 · 오류율`(API 0~1 비율을 화면에서만 %로), 없으면 흐름 이벤트 수다. 숫자는 **같은 네임스페이스의 이웃한 열·행 사이 빈 칸**에서만 그린다. 자원을 건너뛰거나 네임스페이스를 넘거나 양방향인 연결의 숫자는 자원 카드·다른 숫자에 가려지므로 선 위에 그리지 않고, 자원 상세의 '연결' 목록에 방향·상대·수치로 모두 보존한다. 접근 이름에는 항상 수치를 넣는다. 미관측 구조 연결은 점선, 지연된 관측은 흐리게 표시한다.
- 장애가 없어도 관측 경고(통신 오류·차단, 엔드포인트 없음 등)가 있는 자원은 주황 경계와 '관측 경고' 문구로 정상과 구분하고, 상세에 원천 근거를 보인다.
- 장애 자원에는 수준이 적힌 맥동 핀을 붙인다. 장애 자원 선택은 장애 관제실로, 정상 자원 선택은 보조 영역의 자원 상세로 연결된다. 키보드 포커스가 화면 밖 자원에 닿으면 확대 비율을 유지한 채 그 자원으로 이동한다.
- 확대·축소·전체 보기와 범례는 캔버스 아래 별도 행에 있어 노드를 가리지 않는다.

**보조 영역**(오른쪽 320px)은 위에서부터 다음과 같다.

1. 클러스터 상태 제목, 관측 기준 시각, 새로고침.
2. 원천 상태(Kubernetes / Prometheus / Hubble / Envoy): 연결됨 / 확인 필요 / 미관측, 오류 원문 펼치기.
3. 압축 요약: 준비 노드, CPU·메모리 사용/용량(막대), Pod 실행·대기·실패, 최근 1시간 재시작, 진행 중 장애(수준별), 오늘 자동 복구·인계·실패·감지.
4. 탭: 경고 이벤트(한글 사유 제목 + 원문 사유·메시지 그대로) / 네임스페이스별 자원 / 자원 상세(선택 시).

**숫자 `null`은 미관측이다.** 0으로 치환하지 않는다. 합계에 누락된 값이 있으면 부분 합계를 전체처럼 표시하지 않는다. 녹색 준비 점은 수집된 자원 준비 상태만 뜻한다. 전체 관제는 10초마다 갱신한다.

**진행 중 장애**는 지도 옆 고정 목록이 아니라 상단 바 오른쪽 알림 버튼(`진행 중 장애 N건`)에 있다. 버튼은 모든 화면에 있다. 목록은 최근 기록 개수와 무관하게 진행 상태(open·analyzing·action_pending·acting)별 전체 페이지를 조회한다. 일부라도 조회에 실패하면 0건으로 표시하지 않고 `?`와 마지막 조회 목록·실패 안내를 보인다. 누르면 수준 높은 순으로 장애·네임스페이스·상태·경과 시간을 보여 주는 드롭다운이 열린다. 항목을 고르면 장애 관제실로 이동한다. Esc 키(포커스는 버튼으로 복귀)와 바깥 클릭으로 닫힌다. 진행 중 장애가 있으면 버튼이 적색으로 강조된다.

## 장애 관제실

맨 위 **상황 요약**은 한 줄 머리말(목록으로, 번호, 수준, 상태, 경과 시간, 해석 포함 추정 비용), 한글 제목, 영향, 현재 단계와 다음 할 일이다.

데스크톱은 아래 3열이다.

1. **AI 분석 흐름(세로)**: 서버의 `depth`를 세로(위→아래), `lane`을 가로로 사용한다. 신호 → 근거 → 분류 → 그룹 → 병렬 에이전트 → 검증 → 조치 → 결과, 지시·명령·해석 노드를 그대로 그린다. 노드는 두 줄이다: 한글 역할명(또는 단계 이름)과 짧은 상태 / 종류·모델(또는 내용). 처음과 새 단계 추가, 캔버스 크기 변경 때 **흐름 전체를 맞춘다**. 맞춘 결과가 읽기 어려운 배율(0.6 미만)이면 0.6으로 위쪽부터 보여 주고 끌어 이동하게 한다. 예정은 회색 점선, 실행 중은 파란 강조, 완료는 녹색 경계, 실패는 적색, 승격은 주황색, 경로 변경은 보라색 점선, 지시 반영은 파란 점선, 검증은 녹색 선이다. 같은 줄의 병렬 연결은 문구 없이 색·선 모양과 접근 이름으로 구분한다. 노드 버튼이 키보드 진입점이다(별도 단계 목록 없음).
2. **근거 · 한글 해석 / 선택한 단계 · 근거**: 원문은 **같은 종류·출처·한글 해석끼리 한 묶음**으로 보인다. 묶음마다 심각도·출처·건수·시각 범위, **한글 해석이 먼저**, 그 아래 **"영어 원문 보기(N건)"**를 펼치면 원문 전체가 문자열 그대로 나온다. 해석이 없는 원문은 묶지 않는다. 필터(전체/오류/이벤트/로그/상태/에이전트)를 제공한다. 흐름에서 단계를 고르면 그 단계가 인용한 원문만 먼저 걸러 낸 뒤 묶는다(같은 해석이라도 인용하지 않은 원문은 섞지 않는다). 이 열이 **선택 단계 상세**(한글 역할·맡은 일, 상태, 한글 결론, 결론 원문 펼치기, 모델·추론 강도·토큰·비용·시간, 입력 근거 버튼) + **그 단계가 본 근거 묶음만**으로 바뀐다. 입력 근거 버튼은 해당 묶음을 강조하고 원문을 펼친 채 가운데로 이동한다. 응답에 없는 근거는 "원문 없음"으로 표시한다. 인용 역할 버튼은 그 단계를 선택한다.
3. **운영자 대화(상시 표시)**: 운영자 메시지, AI의 지시 해석·대상 역할·적용 시점, 실행 기록(한글 제목, 원문 펼치기), 지시 확인 카드를 구분한다. 기존 엔진 자동 조치의 승인·거절과 운영자 인계 인수도 별도 카드로 유지한다. 자동 조치는 대상·요청 변경 값을 먼저 보이고 전체 매개변수·스냅샷 원문은 접어 둔다. 승인·거절에는 명시 확인이 필요하며 서버가 정책·안전 검사를 다시 수행한다. 인계 인수는 담당 기록일 뿐 변경 허가가 아니다. 진행 중에는 일시정지 / 재개 / 중단을 유지한다.

1100px 이하는 상황 요약 + `흐름 / 근거·해석(단계 선택 시 단계·근거) / 대화` 전환 버튼이다. 버튼은 `aria-pressed`를 갖는다. 단계를 고르면 근거 탭으로 이동한다. 확인 대기 중인 지시가 있으면 대화 버튼에 표시가 붙는다. 긴 상황 요약만 제한된 높이에서 따로 스크롤한다.

운영 상태는 사건 상세와 해석 응답 중 `updated_at`이 더 최신인 사건 스냅샷을 사용하고 같은 시각이면 상세를 우선한다. 상태가 같을 때만 상세의 인수 정보를 보존하며 오래된 인계 정보를 다른 상태에 붙이지 않는다. 인계 카드·메시지 전송 경로·입력 제한·분석 제어·상태 단계는 이 같은 상태를 따른다. 해석 조회 실패가 최신 상세의 운영 상태를 막지 않는다.

조회는 진행 중 2초, 종료 후 10초다. 실행 기록은 `since` 커서로 중복 없이 합친다. 응답이 끝난 뒤 다음 조회를 예약하므로 요청이 겹치지 않으며, 경로 변경 시 중단한다. 흐름 변환·근거 묶음은 메모한다. 근거 이동과 대화의 자동 스크롤은 사용자의 선택·전송 때만 실행한다.

## 운영자 지시와 확인 경계

분석 중 입력은 기존 메시지 API를 사용한다. 종료된 장애는 지시 생성 API를 사용하고, 전송 중 종료되어 메시지 API가 409를 반환해도 동일 입력으로 지시를 만든다.

지시 상태별 화면:

- 계획 수립 중: 진행 표시와 취소.
- 실행 확인 대기: 한글 계획, 작업 종류·대상·수량, 사전 검사 결과와 경로별 변경 전→후, 영향 대상, 재시작, 서비스 중단 가능성, 원복 가능 여부와 방법, 경고를 전부 표시한다. 클러스터 범위 변경은 별도 적색 경고다.
- 확인 문구는 **정말 진행하시겠습니까?**, 버튼은 **진행 / 취소**다. 모든 작업의 사전 검사 통과, 부작용 설명, 계획 해시가 없으면 진행할 수 없다. 확인에는 표시된 계획 해시를 보낸다. 해시 충돌은 성공으로 표시하지 않는다.
- 비밀값 입력 대기: `secret_update.keys`별 비밀번호 입력, 자동 완성 끔, 값의 비저장·AI 비전달 안내. 값은 React 상태·대화·웹 저장소·로그에 넣지 않는다. 전송 전에 입력 DOM을 즉시 초기화하고 실패 시에도 값을 재표시하지 않는다. 응답은 상태와 키만 받는다.
- 실행 중 / 완료 / 실패 / 거절 / 취소 / 원복 중 / 원복 완료는 각각 한글 상태로 표시한다. 완료에는 결과와 검증 원문을 구분하고 원복 가능할 때만 확인 대화 후 원복 요청을 보낸다.

모든 쓰기는 기존 `request()`를 통해 `X-LiveProbe-Client: dashboard`를 보낸다. 이 화면의 확인은 서버 측 권한·계획 해시·사전 검사·부작용 검증을 대신하지 않는다.

## 접근성과 동작

- 인터랙션은 실제 버튼·링크·입력·선택 상자다. 한국어 접근 이름과 보이는 포커스를 제공한다.
- 필터·화면 전환·보조 탭·자원·단계 선택은 `aria-pressed`, 알림 버튼은 `aria-expanded`, 비동기 상태는 `role=status`, 오류와 클러스터 전체 영향은 `role=alert`다.
- 움직임 감소 설정에서는 핀 맥동·흐름 선·진행 표시 애니메이션을 끈다.
- 차트 라이브러리는 추가하지 않는다. 서체는 번들에 내장할 수 있고, 실행 의존성은 `@naria/ui`·`@radix-ui/react-icons`가 있다(P20). 운영 관제와 관제실은 지연 로딩한다.
- 모델 설정의 초안 유지, 버전 충돌, 저장, 기본값 복원과 검토 기록 경로를 유지한다.

## 로컬 검증

`e2e/README.md`에 표본 출처·한계·실행 명령을 기록한다. 단위 시험은 필터·인용 연결·근거 묶음·세로 흐름 배치와 연결면·지도 숨김·네임스페이스 압축 배치·미관측 합계·장애 핀·서비스 보존·명령 상태와 확인 차단을 검증한다. Playwright는 375/768/1440px에서 화면과 측면 영역의 `scrollWidth`/`clientWidth`, 버튼 사각형 겹침, 한국어 컨트롤 잘림, 키보드 진입, 알림 드롭다운, 확인·취소·원복·비밀값·전송 경합을 확인한다. 1440×900·1280×800에서는 운영 관제의 페이지 무스크롤·지도 점유율(55% 이상)·전체 자원 표시, 1440×900에서는 관제실의 페이지 무스크롤·흐름 전체 표시·대화 입력 노출을 확인한다.

모의 API 캡처는 `e2e/artifacts/mock/`, 실배포 읽기 전용 캡처는 `e2e/artifacts/live/`에 나누어 저장한다(같은 이름으로 덮어쓰지 않는다). 배치 검사는 연결선 문구가 자원 카드에 가려지는지도 측정한다. 자동 측정과 직접 이미지 검토를 구분한다. 이 로컬 검증은 실제 배포·실제 클러스터 복구·서버 비밀값 비저장 검증을 의미하지 않는다.


## 통합 코드 조치

통합 모드에서 `/application`은 새 애플리케이션 사건을 접수하는 내부 진입점이다. 새 사건은 K8s 루트 번호를 받고 같은 `/incidents/:id` 관제실로 이동한다. 과거 Application 기록은 원래 ID·출처·퇴역 환경을 보존하며 연결된 기록만 루트 링크를 제공한다.

코드 조치의 원인·변경·시험·승인은 해당 단계의 관제 카드에서 읽는다. 오른쪽의 행동 영역은 운영자에게 실제 결정이 필요할 때 표시한다. K8s 사용량과 Application 역할별 실제 기록을 구분하며 누락값은 미관측이다. 원문·diff·JSON·로그만 요청할 때 펼친다. 연결된 사건의 K8s 단계는 과거 실행 기록이고, 현재 코드 조치와 충돌하는 인수·조치·중단 제어를 보여 주지 않는다. 서버도 직접 요청을 차단한다.

전용 루프백 관제 주소에서 운영자 한 명이 사건을 조회·접수하고 현재 버전 재검증, 사람 병합 확인, 운영 승인을 요청한다. 새 릴리스의 재현·회귀 시험과 dev 사용자 여정 QA는 실행기가 수행한다. 게이트웨이는 서버 전용 조회 키와 별도의 쓰기 서명 키를 사용한다. 변경 요청은 정확한 Host·Origin과 CSRF 증명을 확인한다. 자동 시험 결과와 병합 확인·승인 결정에는 각각의 대상 버전과 시각이 기록된다. 지문이나 상태가 바뀌면 기존 확인을 해제하고 실행 직전에 시험과 승인을 다시 검증한다.

## 운영 화면 계약 (2026-11-21)

- 홈: 영향 서비스·자동 분석/조치·승인 대기를 현재 지표로 표시한다. 조회 실패나 미관측은 0건이 아니다. 전체 기간 미인수 이관은 현재 집계와 분리한다. 우선 대응 목록은 사건 번호·영향·다음 조치를 보여 주고 해당 관제실로 연결한다. 지도 아래 또는 옆의 보조 탐색은 필요할 때 열고 이력 링크는 유지한다.
- 관제실: 넓은 화면은 흐름도 옆에 단계 패널, 좁은 화면은 세로 배치와 보기 전환을 제공한다. 기본은 실제 실행 호출을 따르며 병렬 역할을 바꿀 수 있다. 선택한 카드는 새 이벤트가 도착해도 유지하고, 흐름도의 실행 중 카드를 직접 선택해 현재 작업을 읽는다. 전체 대화·이력은 별도 보기다. 완료 사건은 결과가 먼저 나오며 종료 기록과 저장 표본을 구분한다. 구형 서버에서 코드 조치 경로만 없는 경우 기존 Kubernetes 인수 동작을 유지하고, 상태 조회 오류는 변경 권한을 열지 않는다.
- 실행 표시는 동일 호출·시도에 관측된 지시, 근거와 운영자 메시지 참조, 진행, 공개 답변 및 확정 결론을 나눈다. 구형 기록에 없는 지시를 추정하지 않으며 전체 프롬프트·비밀·내부 추론은 저장하지 않는다.
- Naria의 press·hover·select·expand·enter와 `--nds-ease`를 재사용한다. 실행 중인 흐름만 움직이며 동작 줄이기 설정에서는 반복·전환 모션을 끈다. 상태는 텍스트로도 전달한다.
- `/application`은 장애 목록의 애플리케이션 필터로 연결한다. 기존 사건 북마크는 해당 사건으로 연결한다. 접수용 카탈로그 조회가 실패하면 기존 사건을 계속 열 수 있고, 접수 영역에는 응답에 따라 구형 설치(404), 조회 권한(403), 조회 지연(500)과 다시 확인 버튼이 표시된다.

## 공통 관제 카드 (2026-11-21)

흐름도는 사건을 이해하거나 판단하는 단위로 구성한다. 감지, 근거 수집, 대응 경로 결정, 원인 조사, 독립 검증, 조치 실행, 시험·빌드, dev 검증, 운영 승인, 복구 확인, 결과·소명, 운영자 인계 중 실제 기록이 있는 카드가 나타난다. 조치 실행은 실제 대상과 조치별로 구분한다. 에이전트 역할·재시도·대기와 완료는 같은 카드 안에서 읽는다. 이전 회차와 실제 호출 모델을 유지한다.

오른쪽은 선택한 카드에서 확인해야 할 사실부터 제시한다. 예를 들어 시험·빌드에서는 원래 실패한 업무 동작의 수정 전후 결과와 추가한 시험을 먼저 표시한다. 현재 실행과 기록된 실행을 구분하고 다른 작업이 시작돼도 읽는 카드를 유지한다. 원문·diff는 인용 옆에서 요청한다. 운영자가 실행하는 결정과 흐름도 탐색을 구분한다. [카드별 합의와 검증 기준](../docs/plans/semantic-incident-cards-2026-11-21.md)

단계 흐름과 전체 흐름은 같은 두 줄 카드를 사용한다. 첫 줄에는 아이콘·단계명·상태, 둘째 줄에는 역할이 표시된다. 두 보기에서 기록된 화살표·분기·합류·재조사 경로를 그대로 읽을 수 있다. 단계 흐름은 선택한 카드를 가운데 둔다. 넓은 창에서 대응 경로 결정을 보면 오른쪽에 원인 조사와 독립 검증 반 장이 나타난다. 원인 조사를 누르면 그래프가 그 위치로 부드럽게 이동하고 독립 검증 전체가 보인다. 가려진 노드가 있는 쪽에는 흐림을 적용한다. 방향키로도 카드를 선택할 수 있다. 좁은 화면에서는 단계 그래프 아래에 선택한 상세를 둔다. 같은 단계의 내용 갱신은 읽는 위치를 유지하고 동작 줄이기에서는 새 위치를 즉시 표시한다.

실제 역할이 시작되거나 실행기가 일감을 인수하면 해당 카드의 청록 테두리가 주기적으로 퍼지고 ‘작업 중’ 배지와 담당 역할이 나타난다. 다른 카드를 읽는 동안에도 작업 위치를 확인할 수 있다. 동작 줄이기에서는 고정 테두리와 배지를 사용한다. 같은 단계에 여러 역할이 있으면 담당 역할을 함께 표시하고, 다른 단계에서 동시에 작업하면 각 카드를 강조한다. 일감을 기다릴 때에는 대기 중인 단계와 상태를 표시한다. 현재 작업의 단계명을 누르면 해당 상세가 열리고, 직접 연결된 단계 사이를 선택하면 연결선에 이동 방향이 표시된다.
