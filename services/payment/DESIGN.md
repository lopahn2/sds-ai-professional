# 결제 화면 설계

## 0. 참고 기록
- P18 계획 A3·A4·D: 실제 업무를 먼저, 관측·장애 제어를 아래에 배치한다.
- 로컬 운영 도구 색상·서체·사용성 자료를 조회했다. 외부 자산이나 네트워크 글꼴은 쓰지 않는다.
- 기존 대시보드는 소유 범위 밖이므로 새 독립 화면에만 적용한다.

## 1. 분위기와 정체성
절제된, 명확한, 실용적인 운영 도구. 운영형 방향을 택한다. 업무 담당자와 장애 실험 운영자가 대상이다.
상단 환경 배지와 하단 황색 장애 실험 구획이 업무와 실험의 경계를 만든다. 장식용 도형·그라데이션·영문 제목은 없다.

## 2. 색상
배경 #f3f5f7, 표면 #ffffff, 머리글 #16232d, 본문 #1c2b36, 보조 글자 #51616d, 테두리 #d5dde3.
강조 #11695b, 성공 #126344, 경고 #82530b·배경 #fff7e5, 오류 #a82631·배경 #fff0f0.
중립 85%, 강조 10%, 상태색 5%. 본문 대비는 최소 4.5:1을 목표로 한다.

## 3. 글꼴
외부 다운로드 없이 -apple-system, BlinkMacSystemFont, 'Apple SD Gothic Neo', 'Malgun Gothic', sans-serif.
본문·보조 14px 이상, 입력 16px, 절 제목 20px, 화면 제목 30px, 주요 수치 28px. 굵기 400·600·700.
한글 줄높이 1.6, 자간 0, word-break:keep-all, overflow-wrap:anywhere. 숫자는 표형 숫자.

## 4. 간격과 배치
기본 단위 4px, 간격 4·8·12·16·24·32px. 내용 최대 너비 1120px, 데스크톱 여백 32px, 모바일 16px.
업무 입력 320px와 이력 나머지의 비대칭 2열. 760px 이하에서는 1열. 375·768·1440px를 검증한다.
전체 문서만 세로 스크롤한다. 표 대신 줄바꿈 가능한 목록을 사용하며 가로 스크롤은 만들지 않는다.

## 5. 구성요소와 상태
환경 배지, 업무 요약, 레이블이 있는 폼, 이력 목록, 상세 구역, 알림 영역, 장애 버튼을 재사용한다.
버튼은 최소 44px, 모서리 8px, 기본 실선·호버 진한색·누름 테두리·초점 3px 윤곽선·비활성 반투명.
요청 중 버튼을 잠그고 '처리 중…'을 표시한다. 빈 목록은 설명, 오류는 role=alert, 성공은 role=status로 알린다.
활성 장애 버튼은 aria-pressed=true와 '켜짐' 글자를 함께 표시한다. 제거·취소도 키보드로 작동한다.

## 6. 움직임과 상호작용
장식 애니메이션 없음. 버튼 색 변화만 120ms, reduced-motion에서는 제거. 강제 자동 스크롤 없음.
실험은 관측된 상태로만 갱신한다. 종료·메모리 장애에는 위험 확인 대화상자를 제공한다.

## 7. 깊이와 표면
그림자·흐림 없음. 1px 테두리와 바탕 명도, 12px 구역 모서리만 사용한다.

## 8. 접근성과 성능
명시적 레이블, 의미 있는 제목 순서, 기본 폼·버튼, aria-live, 키보드 초점, 상태의 색상 외 표기를 적용한다.
검증 범위는 실제 화면·업무·장애 버튼과 가로 넘침이다. 전체 접근성 감사·현장 성능 수치는 이 작업 범위가 아니다.
새 화면이므로 비교 기준 없음. 로컬 데스크톱·모바일 뷰포트, 추가 네트워크 제한 없는 첫 화면 LCP 2.5초 이하를 목표로 한다.
