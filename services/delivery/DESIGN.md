# 업무 화면 설계 규칙

## 조사와 대상
P18 A3·A4·D 계약을 기준으로 새로 만드는 회원·배송 업무 화면이다. 운영자가 업무 요청과 장애 상태를 한 화면에서 확인한다. 외부 디자인·글꼴·이미지·스크립트는 사용하지 않는다. 지역 설계 자료에서 두 단계 표면 분리, 한글 14px 이상, 되돌릴 수 없는 동작 확인, 초점 순서와 문서 순서 일치를 참고했다.

## 분위기와 식별
주 방향은 단정한 운영 도구다. 어두운 상단 식별 띠, 넓은 밝은 업무 영역, 아래쪽 경고색 장애 구역으로 목적을 구분한다. 장식용 그림·그라데이션·유리 효과·큰 그림자는 사용하지 않는다.

## 색
바탕 #f3f5f7, 표면 #ffffff, 상단 #15252d, 본문 #172c35, 보조 #53656f, 구분선 #d4dde2, 강조 #08675e, 강조 배경 #e8f4ef, 위험 #a82e30, 위험 배경 #fff2f0. 표면·바탕 80%, 상단·본문 15%, 강조·위험 5%가 원칙이다. 일반 글자 대비는 4.5:1 이상을 목표로 한다.

## 글자
지역 글꼴만 사용한다: -apple-system, BlinkMacSystemFont, 'Apple SD Gothic Neo', 'Malgun Gothic', sans-serif. 본문 15px·행간 1.65, 보조 14px, 구역 제목 20px, 화면 제목 32px, 두께 400·600·700. 한글은 keep-all, 긴 식별자·응답은 anywhere로 줄바꿈한다. 숫자는 고정 폭 수치 속성을 쓴다.

## 간격과 배치
4px 단위, 간격 8·12·16·24·32px. 최대 폭 1120px, 좌우 여백 24px(모바일 16px). 760px 이상은 업무 입력 1열 + 결과 1.5열, 그 이하는 1열이다. 목록은 가변 격자 행으로 만들고 페이지 전체만 세로 스크롤한다. 375·768·1440px 가로 넘침이 없어야 한다.

## 구성요소와 상태
입력·선택·버튼 높이 최소 44px, 모서리 8px. 각 입력은 연결된 한국어 이름표를 둔다. 기본·호버·눌림·초점(3px 외곽선)·비활성 상태를 구분한다. 업무 결과는 대기·빈 목록·성공·실패 문구를 제공하고 상태 영역은 aria-live를 사용한다. 장애 버튼은 aria-pressed와 켜짐/꺼짐 글자로 상태를 중복 표현한다. 재시작·메모리 증가·이벤트 루프 정지 전에 확인 대화상자를 사용한다.

## 동작과 표면
그림자·배경 애니메이션 없음. 호버·초점만 즉시 바뀐다. 줄어든 동작 선호에서도 같은 정적 동작이다. 자동 상태 조회는 5초마다, 업무 목록은 사용자가 요청할 때 갱신한다.

## 접근성과 성능
키보드 순서는 문서 순서를 따른다. 성공·실패는 색만으로 전달하지 않는다. 외부 폰트·CDN 없음. 목표는 로컬 비제한 네트워크, 375px 첫 방문 /에서 최대 콘텐츠 렌더링 2.5초 미만이다. 신규 화면이라 사전 측정 기준값은 없다. 이는 목표이며 실제 사용자 성능 통과 주장이 아니다.

## 검증 행렬
375·768·1440px에서 기본·입력 결과·실패·장애 켜짐/꺼짐을 실행 중인 컨테이너와 브라우저로 확인한다. 주문 화면은 기존 정적 매핑 비활성 설정 때문에 기본 실행 경로와 명시적 매핑 활성 실행을 따로 기록한다. 새 라이브러리나 자바 코드 변경은 하지 않는다.
