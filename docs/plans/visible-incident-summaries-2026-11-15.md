# 장애 관제 정보 표시 수준 정리

- 요청: 2026-11-15, 제목 → 문제 상황·원인 요약 → 접힌 원문 로그.
- 범위: Kubernetes와 Application의 운영 현황, 사건 상세, 지난 사건·지시, 분석·검증, 변경·시험·승인 정보.
- 합의: 사용자의 전체 적용 지시를 기준으로 진행한다. Jira를 사용하지 않는다. 데이터·이력·인증·실행 정책은 변경하지 않는다.

## 적용 기준

1. 제목 아래에 증상과 기록된 원인 또는 원인 미확정 상태를 표시한다.
2. 판단, 근거 요약, 검증, 다음 행동, 위험, 원복 방법, 이력은 펼치기 없이 읽을 수 있다.
3. 로그, JSON, 명령 출력, diff 등 원문만 명시적으로 열 때 표시한다.
4. 원인을 추정해 확정하지 않는다. 한국어 설명이 없는 기록은 미기록으로 표시하고 원문을 보존한다.
5. 실시간 공개 답변, 지도 탐색, 단계 이동, 승인 확인 및 지문 변경 시 확인 해제를 유지한다.

## 구현 순서

- 기존 접힘과 의미 정보/원문 혼합 영역 전수 확인.
- Kubernetes 카드·이력·클러스터 진단을 상시 표시하고 증상/원인 요약 보강.
- Application의 분석·시험·변경·이력을 상시 표시하고 원문 렌더링 분리.
- 원문 지연 표시, 기본 요약 노출, 승인 보호, 화면 너비별 동작을 검증.
- 빌드 후 실행 중인 로컬 화면에 반영하고 결과 기록.

## 구현 전 검토

- 단순히 모든 details를 open으로 바꾸면 원문까지 노출되므로 의미 정보만 별도 일반 영역으로 이동한다.
- 과거 사건의 전체 숨김과 공개 답변 숨김도 제거한다.
- 승인 대상은 항상 보이되 체크박스·권한·지문 유효성 검사와 명시 제출은 유지한다.
- 지도/탭/페이지 이동은 탐색 기능으로 유지한다. 새 사건·인증 입력은 작업용 폼이므로 정보 표시와 구분한다.
- 초기 화면 건수와 “할 일 없음”의 모순도 기록된 집계를 기준으로 바로잡는다.

## 진행 및 검증

- Kubernetes와 Application 모두 구현 완료. 원문 지연 렌더링·명시적 승인·데이터 보존 유지.
- 종료된 사건의 실행 표시는 저장 당시 상태로 구분하며 단계 원본 상태는 바꾸지 않는다.
- 빌드·타입 검사 및 단위 검사 177건, Application 정적 검사 24건 통과.
- Kubernetes 화면 검사 39건과 최종 이력·스트리밍 검사 30건 통과(중복 9건, 고유 60건). 375·768·1440px 검증.
- Application 정보 계층·승인 보호 등 9개 시나리오와 기존 목록·이력·초안 보존 11개 시나리오 통과.
- 실제 K8s 사건을 읽어 정보 계층 반영 확인. 운영 데이터 쓰기·삭제 없음.
- Application의 기존 실행기 연결 미확인 상태는 UI가 그대로 표시하며, 사건 상세와 승인은 합성 API로 검증했다.
- VITE_APPLICATION_URL은 로컬 확인 시 Application 화면 주소를 지정하는 선택 설정이다. 기본값은 기존 Application 주소다.
- 검증 범위는 표시 변경과 관련 회귀 검사이며 백엔드 전체 시험을 재실행한 것은 아니다.
