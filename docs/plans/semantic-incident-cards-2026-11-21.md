## 합의한 범위

Kubernetes 단독, Application 단독, 연결 사건이 감지·근거 수집·대응 경로 결정·원인 조사·독립 검증·조치 실행·시험 및 빌드·dev 검증·운영 승인·복구 확인·결과 및 소명·운영자 인계를 공유한다. 실제 조치는 대상별로 나누고 반복 호출과 상태 전이는 해당 카드의 기록으로 둔다. 반려는 기존 원인 조사로 돌아간다. 오른쪽은 선택한 카드에 고정하고 단계 이동은 흐름도가 맡는다. 원문 로그와 diff는 요청 시 제공한다.

## 검증 경계

운영 사례는 읽기 전용으로 대조한다. 운영자 변경, 승인 경합, 실행기 보고와 재검증은 격리 환경에서 검증한다. 과거 이미지와 데이터는 복원하거나 재배포하지 않는다. 모델 호출을 재실행해 역사 기록을 채우지 않는다.

## 카드 사이 이동 모션

운영자가 다른 카드를 선택하거나 자동 추적 중 실제 단계가 바뀔 때 이동 방향과 도착 지점이 한눈에 보이는 것을 완료 기준으로 삼았다. 두 카드가 직접 연결돼 있으면 해당 선을 따라 360ms 동안 강조가 흐른다. 선택 카드는 460ms 안에 확대 후 제자리로 돌아오고 오른쪽 상세는 이동 방향에 맞춰 400ms 동안 나타난다. 최초 조회와 같은 단계의 재선택·폴링에서는 전환을 재생하지 않는다. 동작 줄이기에서는 선택과 포커스만 이동한다.

대시보드 단위 시험 219개, 375·768·1440px에서 실행한 모션 브라우저 시험 12개가 통과했다. 자동 추적, 키보드 선택, 좁은 화면의 포커스, 원래 연결선의 정방향·역방향을 검사했다. 운영 대시보드 리비전 60에서 61로 반영한 뒤 4175가 제공한 정적 파일 7개의 지문을 대조했다. #1501과 inventory 원본 사건에서 실제 애니메이션의 방향·재생 횟수·시간을 확인했고, 모바일 동작 줄이기에서는 이동 애니메이션이 0회였다.

## 클릭으로 넘기는 카드와 현재 작업 위치

Kubernetes와 Application 관제실에 같은 카드 탐색 방식을 적용한다. 선택한 카드를 중앙에 두고 양옆 카드 한 장과 그 너머 카드의 절반을 보여준다. 첫 카드와 마지막 카드에는 실제로 이어지는 쪽에만 흐림을 표시한다. 운영자가 옆 카드를 클릭하면 카드 열이 한 칸 이동하고 상세가 함께 갱신된다. 키보드로도 같은 단계를 선택할 수 있다. 휠·스와이프로 카드 열을 조작하는 방식은 사용하지 않는다.

현재 작업의 위치와 열람 중인 단계는 따로 추적한다. 역할이 시작·종료되거나 실행기 인수 상태가 바뀌면 해당 카드와 전체 흐름의 작업 표시를 갱신한다. 현재 작업을 선택하면 그 카드의 상세가 열린다. 완료 기준은 ‘대응 경로 결정 → 원인 조사’의 실제 클릭에서 반쯤 보이던 독립 검증이 온전히 나타나는 것, 읽고 있는 단계와 병렬 역할을 동시에 식별하는 것, 보관 표본·승인 대기를 작업 중으로 표시하지 않는 것이다.

2026-11-21 대시보드 리비전 62를 4175에 반영했다. 단위 시험 222개와 375·768·1440px 브라우저 회귀 시험 36개가 통과했다. 격리 시험은 모델 역할의 시작·완료, 병렬 역할, 키보드 선택, 휠·스와이프에도 유지되는 위치, 동작 줄이기를 포함한다.

운영 브라우저에서 #1501과 inventory 사건을 1440px로 열어 직접 클릭했다. 대응 경로 결정이 가운데일 때 양끝 카드는 각각 50% 보였고, 원인 조사를 누르면 카드 열이 14개의 서로 다른 위치를 거쳐 정렬되면서 독립 검증 카드가 전부 보였다. 휠 입력 뒤 가로 이동 거리는 0px였다. 375px의 동작 줄이기 설정에서는 즉시 정렬됐다. 당시 inventory는 전체 흐름에 ‘근거 수집 · 실행기 인수 대기’로 표시됐다. 운영에 새 모델 호출을 보내지 않았으며 실제 역할 전환 표시는 격리 브라우저에서 검증했다.

## 원래 그래프를 유지하는 클릭 이동

단계 보기와 전체 보기에서 같은 작은 두 줄 카드와 같은 방향 화살표를 사용한다. 운영자가 카드를 누르면 그래프가 선택한 단계로 부드럽게 이동한다. 열람 중인 카드에는 선택 테두리가, 실제 실행 중인 카드에는 ‘작업 중’과 바깥으로 퍼지는 테두리가 표시된다. 여러 에이전트가 동시에 일하면 각 단계가 표시된다. 동작 줄이기를 설정하면 위치와 상태를 즉시 갱신한다.

4175 대시보드 리비전 63에서 K8s #1501의 카드 7개·연결선 6개와 Application #6a14d02aeb9b4bd99303cea02ade65b4의 카드 10개·연결선 13개를 원기록과 대조했다. 단계 보기와 전체 보기에서 분기와 이전 단계로 돌아가는 선이 일치했다. 실제 클릭은 여러 프레임으로 이동했고, 넓은 창에서 다음 열 카드의 절반이 보였다. 최종 번들의 단위 시험 222개, 375·768·1440px 브라우저 시험 39개, 작업 표시의 프레임 변화와 축소 모션 시험 6개가 통과했다.

## 근거 재수집과 작업 위치의 실제 검증

위 Application 사건의 dev 재수집은 처음에 외부 실행기가 연결되지 않아 대기했다. 역할별 실행기를 연결한 뒤에는 2회차 수집 결과에 Pod 로그가 없다는 이유로 동시 수집한 Deployment와 rollout 관측도 버리고 이관했다. 수정한 처리기는 보완 회차에서 현재 대상의 Deployment를 관측했고 로그 조회가 빈 배열로 성공한 경우 해당 구간을 그대로 기록한다. 최초 실패는 원래 시각과 지문을 유지하며 인용할 수 있다. 근거가 누락됐거나 대상이 다른 응답은 거절한다.

API 리비전 91과 모델 작업자 리비전 4로 교체하며 기존 Kubernetes 사건 1,491건, Application 사건 9건, 이벤트 220건과 작업 37건의 식별 지문을 대조했다. 4175에서 위 사건에만 보완 요청을 보냈다. 3회차 수집 결과는 2026-11-21 16:07:02 KST 기준 배포·롤아웃 근거 2건과 새 로그 0건이다. 과거 수집 결과 13건은 이전 회차에 보존했다. 소스 실행기가 dev 이미지 `83462e2f…`의 파일 6개를 확인해 스냅샷 `f7417d4a…`를 전달했다.

실제 브라우저에서 16:07:00 인수 대기, 16:07:03 근거 수집 카드의 실행기 파동, 16:07:43 원인 조사 카드의 분석 에이전트 파동을 관측했다. 분석 카드 테두리는 650ms 동안 41개의 서로 다른 그림자 값으로 그려졌다. 사건 기록 247번에서 분석이 끝나자 파동도 꺼졌다.

분류와 분석이 실제로 수행됐다. `gpt-6.2-sol` 분석 결과, 최초 오류와 관련된 무조건 실패 분기는 현재 소스에 없었고 남은 경로는 명시적으로 활성화하는 `code_bug_validation` 장애 주입이었다. 새 업무 요청에서 재현 또는 복구를 관측하지 못해 사건은 `application_fix_not_supported`로 운영자 확인에 도달했다. 이번 회차의 업무 배포는 0건이다.

최종 소스에서 Application 전체 격리 시험 321개와 하위 검사 98개가 통과했다. 재수집 요청의 중복 처리, 빈 로그 구간의 보존, 운영자 이관 후 재수집, 배포 지문이 다른 빌드 결과의 거부를 포함한다.
