## 직접 확인한 화면 (캡처 검토)

- 1440×900: 운영 관제(승인 대기 1건 포함), 장애 관제, 승인 대기 관제실, 분석 중 관제실(단계 펼침·단계 지시 전송·원문 상세 패널), 종료된 장애의 지난 단계와 운영자 지시 카드(실행 확인 대기), 인계 관제실(1차).
- 375×844: 운영 관제, 장애 관제, 승인 대기 관제실, 분석 중 관제실 대화 탭.
- 캡처 검토에서 찾아 고친 것:
  - 1차에서 운영자 말풍선 글자가 바탕색과 같아 보이지 않던 문제.
  - 2차 작업 중 승인 카드가 대화 영역 맨 위에서 납작하게 줄어들어 승인 버튼이 가려지던 문제(카드가 줄어들지 않게 하고 E2E에 버튼 가시성 검사를 추가).
  - 좁은 화면에서 메뉴 짧은 이름이 글자 단위로 꺾이던 문제, 환경 표시가 메뉴 줄에 노출되던 문제.

## 확인하지 않은 것

- 비밀값 입력 상태, 실패·원복 상태의 지시 카드, 변경 요청 카드, 종료 카드는 스타일을 적용했지만 캡처로 확인하지 않았다(해당 E2E는 통과).
- 검토 기록·설정 화면은 캡처만 했고 세부 검토는 하지 않았다. 768px 화면은 자동 시험만 통과시켰고 눈으로 확인하지 않았다.
- 키보드만으로의 전체 탐색, 화면 낭독기, 다크 테마.
- Docker 이미지 빌드(`Dockerfile`의 `COPY vendor` 추가)는 이 환경에서 실행하지 않았다.
- 실제 백엔드와의 연동(`counts`가 내려오는 서버 응답에서의 집계 표시).

**백엔드 전체 시험에 대해**: 브랜치 전체 실행에서 54건이 실패·오류였다. 수집 단계 오류 4건(`No module named 'evaluation'`)은 CI에서도 나는 기존 문제다. 다수는 이 환경에 Docker·클러스터가 없어서 나는 것으로 보이지만 시험별로 확인하지 않았다. 확인이 필요한 것:
- `test_p20_room_explain.py`의 DB 통합 시험이 단독으로는 통과하지만 전체 실행에서는 `rag_chunks.tsv`(생성 열) 삽입 오류로 실패했다. 같은 오류가 기존 RAG 시험(`test_api.py::test_citation_api_...`, `test_rag.py` 등)에서도 났다. 실행 순서나 로컬 DB 설정에 따른 것인지 확인하지 못했다.
- `test_p18_w6_narrative.py::test_agent_and_verify_cards_and_planned_nodes_accept_steering`가 전체 실행에서 실패했다. 서사 시험만 묶어 돌렸을 때는 통과했다. 이번 변경과의 관련 여부를 확인하지 못했다.

**직접 확인한 화면**: 1440×900에서 종료된 복잡 사건(#971)의 접힌 단계 목록, 수준 판단·그룹 카드 펼침, 반론 검토 카드(인용 원문 펼침·반대 근거), 복구 계획 카드(참고 문서), 검증 카드, 상황 요약의 AI 사용 요약. 375×844에서 대화 탭의 그룹 카드(가로 넘침 없음).

**확인하지 않은 것**: 실제 백엔드 응답으로 화면을 띄운 적은 없다(모의 fixture만 사용, 인용문·참고 문서는 모의 값). 진행 중 사건에서 새 필드가 실시간으로 채워지는 동작, 키보드 탐색, 768px 화면.
