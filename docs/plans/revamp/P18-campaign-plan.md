# P18 시스템 장애·비용 비교 캠페인

## 승인된 목표와 범위

사용자 요청: 서버를 재기동하고 대시보드를 확인한 뒤 만든 시스템을 모두 실행한다. 시스템별 애플리케이션 장애 30건을 설계하고 실제 주입·원복·기록한다. 단순·보통·복잡 그룹별 비용(불가하면 토큰)을 비교하고 모두 저장한다.

- 시스템 6개: order(order·inventory), payment, member, catalog, delivery, notification. 총 180개 시나리오이며 7개 서비스에 210건을 잘못 배분하지 않는다.
- dev·stg·prd에 각 7개 Deployment를 실행한다. 캠페인은 우선 dev에서 한 번에 한 건만 수행한다. stg·prd는 기준선 상태로 유지한다.
- 분석·원복·집계는 부모가 책임지고, Python·Node·Java 앱 구현은 별도 작업자가 맡는다. 독립 검토 후 실제 실행한다.
- 허용: 기존 rancher-desktop 클러스터의 가역적 배포·재기동·앱 장애 실험·필요한 환경 DB/권한/수집 설정, 로컬 파일 저장. 금지: PR 자동 병합, 비밀값 열람·로그 출력, 외부 공개·push, 데이터베이스 삭제, 새 클러스터/CNI 교체.
- 기존 liveprobe-target은 새 환경의 정상 확인 후 Deployment만 0으로 축소하며 삭제하지 않는다. loadgen은 추가하지 않는다.
- Jira는 사용자가 연결하지 않기로 한 기존 결정을 유지하며 로컬 계획/실행 원장으로 추적한다.

## 검증 계약

점수 최적화 실험이 아니라 관측 기반 캠페인이다. 시험 결과에 맞춰 시나리오나 판정 기준을 바꾸지 않는다. 최초 고정 카탈로그의 SHA256·버전·실행 순서를 저장한다.

완료 기준:
1. 배포된 API readyz=200, 마이그레이션 head=0010, 대시보드 정적 자산 지문 일치 및 실화면 확인.
2. dev·stg·prd에 시스템 6개/서비스 7개가 실행되고 18개 업무 화면에 접속 가능.
3. 시스템마다 고정 30개(설계 단순/보통/복잡 각10개), 총180개 고유 ID가 존재.
4. 건별 기준선·주입값·장애 실제 관측·감지 사건·분석/이관·조치·원복·건강 재확인·토큰·오류를 저장. 미감지/시간초과/실패도 원장에 남기며 성공으로 대체하지 않음.
5. 다음 건 전 원복 검증, 캠페인 후 이미지·리소스·복제수·설정 및 헬스 기준선 일치.
6. 원본 JSONL/JSON·CSV·사람이 읽는 보고서를 생성하고 Python으로 개수·중복·집계를 검증.

## 비용 집계 원칙

- 설계 그룹(planned_group)과 실제 라우터 그룹(observed_group)은 별개. 원하는 비율을 맞추려고 라우팅을 고정하거나 낮추지 않는다. HIGH_RISK도 실제 결과로 보존한다.
- agent_runs의 실제 input_tokens/output_tokens, 호출 수·모델·추론 강도·실패/재시도·duration_ms를 모은다. 해석/라우터/주 분석/후속 호출은 role별로 구분한다.
- 구독형 Codex이므로 실제 달러 청구액은 미관측이다. 토큰 총계가 주 비교값. estimated_cost_usd는 버전 있는 API 가격표 환산 추정치이며 구독 청구액/실제 절감액으로 표현하지 않는다.
- 누락 토큰/가격은 null과 결측 수로 남긴다. 0으로 대체하지 않는다. 전체 감지 관련 사건을 부모/연쇄 사건 ID로 연결해 중복 합산을 막는다.
- 서로 다른 시나리오 그룹의 평균 차이는 기술통계다. 동일 사건의 교차 전략 실험이 아니므로 인과적 비용 절감률을 주장하지 않는다.

## 중단·원복 조건

- 노드 MemoryPressure/Ready 이상, 원복 실패, 앱 외 영향, 비밀정보 노출 가능성, 모델 한도/인증 오류: 새 주입 중단, 가능한 범위 원복 후 체크포인트.
- 각 건은 유한한 감지·분석·원복 제한 시간을 가진다. 전체 실행기는 deadline·signal 취소·finally 원복을 지원해야 한다.
- 구독 한도시 실제 관측 결과와 미실행 건을 구분해 저장하고 체크포인트부터 재개한다. 장기 작업을 세션 밖에 지속하려면 부모 작업의 수명/알림을 별도로 확인한다.

## 현재 관측과 결정

- 사전 백업: .e2e-tmp/P18-campaign/backup-20261025-092358 (DB dump·리소스 선언, 비공개 로컬 보존).
- 기존 DB head=0008, 새 앱 코드 head=0010. API 이미지는 기존 의존성 런타임을 재사용하되 app·전체 alembic을 함께 넣는 증분 빌드로 배포한다. 클린 의존성 재빌드로 보고하지 않음.
- 라우터가 지연/풀 지표 키 존재만으로 지연이라고 판정하는 결함을 재현하고 값 기반 판정으로 수정함. 관련133시험 통과, 전체 회귀 필요.
- 장애 캠페인은 change_auto_create=false로 자동 PR 작업 생성을 막는다. 분석의 코드 수정 필요 판정 자체는 보존한다. 기본값 true 및 off 동작 2시험 포함 신규7시험 통과.
- release 장애는 ConfigMap 파일 대신 이미지 ENV RELEASE_FAULTS JSON에 넣는다. 재시작에 유지되고 정상 이미지 rollback으로 제거된다. runtime 장애는 파드 emptyDir에 저장해 컨테이너 재시작과 파드 교체의 차이를 관측한다.
- OMH 네이티브 루프 상태 도구는 service_unavailable을 반환했다. 로컬 체크포인트로 실제 실행 증거를 보존하고 도구 상태를 실행 완료로 보지 않는다.
