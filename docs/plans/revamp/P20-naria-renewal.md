- 기준 디자인 시스템: `lopahn2/naria-design-system` main(`d536b75`, 컴포넌트 84개). 디자인 시스템 자체는 수정하지 않는다.

## 1. 시스템과 운영자 흐름

LiveProbe는 Kubernetes 이상 신호를 사건으로 묶고, 난이도·위험도에 따라 AI 에이전트 그룹이 분석한 뒤 **허용된 조치만 실행하거나 운영자에게 넘기는** 시스템이다. 운영자가 화면에서 하는 일은 네 단계다.

| 단계 | 운영자의 질문 | 화면 | 운영자의 행동 |
| --- | --- | --- | --- |
| 1. 파악 | 지금 문제가 있는가? 내가 결정할 것이 있는가? | 운영 관제 `/` | 대응 대기열 확인, 지도에서 위치 확인 |
| 2. 선별 | 어떤 장애부터 볼 것인가? | 운영 관제 대기열, 알림 버튼, 장애 관제 `/incidents` | 승인·인수 대기 → 조치 중 → 분석 중 순으로 진입 |
| 3. 대응 | AI가 무엇을 근거로 무엇을 하려는가? 승인해도 되는가? | 장애 관제실 `/incidents/:id` | 조치 승인·거절, 인계 인수, 후속 지시, 종료 |
| 4. 확인 | 실제로 복구됐는가? 기록은 남았는가? | 관제실 처리 결과, 검토 기록 `/ledger` | 결과·검증 확인, 재발 여부 확인 |

운영자 결정이 **없으면 멈춰 있는** 상태는 두 가지뿐이다: `action_pending`(조치 승인 대기)과 인수되지 않은 `handed_off`(운영자 인계). 나머지 진행 상태(`open`·`analyzing`·`acting`)는 AI가 스스로 진행한다. 이 구분을 화면 전체의 우선순위 기준으로 삼는다(`dashboard/src/responseQueue.ts`).

## 2. 리뉴얼 전 UX 문제 (모의 API 1440×900 캡처 기준)

1. **첫 화면이 "내 차례인가"에 답하지 않는다.** 운영 관제 상단의 `진행 중 / 승인 대기 / 미인수 이관`이 서버 집계가 없으면 모두 `미관측`으로 크게 표시됐고, 진행 중 장애는 상태만 있는 한 줄이라 무엇을 해야 하는지 알 수 없었다.
2. **알림·목록이 수준(심각도) 순이다.** 승인을 기다리며 멈춰 있는 단순 장애가 AI가 분석 중인 고위험 장애보다 아래에 놓였다.
3. **장애 목록의 빠른 필터가 끝난 결과뿐이다.** `자동 복구 / 운영자 종료 / 처리 실패 / 운영자 이관`만 있고 `승인 대기`·`분석 중`은 접힌 상세 필터 안에 있었다. 행에서도 운영자 결정이 필요한지 구분되지 않았다.
4. **관제실의 다음 할 일이 약하다.** `다음 …` 한 줄이 12px 보조 문구였고, 결정 카드(승인·인수)는 대화 영역 안에서 직접 찾아야 했다.
5. **시각 언어가 제각각이다.** 메뉴 아이콘이 문자(▦ ◎ ☷ ⚙)였고, 색·곡률·서체가 디자인 시스템과 달랐으며, 디자인 시스템이 쓰지 않는 보라색이 다이어그램에 있었다.

## 3. 1차 범위와 판단

### 3.1 디자인 시스템 연결

- `@naria/ui` 1.0.1을 `dashboard/vendor/naria-ui-1.0.1.tgz`로 포함하고 `file:` 의존성으로 설치한다(레지스트리 미게시). `Dockerfile`은 `npm ci` 전에 `vendor/`를 복사한다. 실행 의존성 `@radix-ui/react-icons`(디자인 시스템의 peer)가 추가된다.
- `main.tsx`에서 `NariaProvider`(light, modern)로 앱을 감싸고 `@naria/ui/styles.css`를 불러온다.
- `src/naria.css`가 기존 스타일 변수(`--text`, `--accent`, `--line` …)를 디자인 시스템 토큰(`--nds-*`)에 연결한다. 기존 화면의 마크업과 클래스는 유지하므로 화면 계약(DESIGN.md)과 기존 시험의 선택자는 그대로다.
- 서체는 디자인 시스템의 Wanted Sans(내장)로 바뀐다. 다이어그램 작업면은 디자인 시스템 다크 토큰 값으로 맞추고 보라색(경로 변경·이벤트 연결)은 청록으로 바꿨다.

**판단 — 서체 내장 비용:** 디자인 시스템 CSS가 서체를 내장하고 있어 CSS 번들이 약 45 kB → 약 1.9 MB(gzip 약 1.3 MB)로 커졌다. DESIGN.md의 "웹 폰트 0개" 원칙과 다르다. 디자인 시스템 기준 리뉴얼이라는 요청에 따라 적용했고, 로컬 LCP 예산 영향은 검증 항목에 기록한다.

### 3.2 UX 변경

| 화면 | 변경 | 사용한 디자인 시스템 컴포넌트 |
| --- | --- | --- |
| 공통 틀 | 메뉴 아이콘을 Radix 아이콘으로 교체. 분석 계정·환경 상태를 점+문구로 표시. 알림 목록을 "대응 필요 먼저" 순으로 정렬하고 항목마다 짧은 다음 행동을 표시. 알림 버튼은 운영자 결정이 필요할 때만 경고색 | `StatusIndicator` |
| 운영 관제 | 상단 "장애 현황"을 **"지금 대응할 일"**로 교체: 한 줄 상황 문장, `승인 대기 / 미인수 이관 / 진행 중` 집계, 대응 순서로 정렬한 장애 카드(다음 행동 배지·위치·수준·경과). 집계는 서버 값 우선, 없으면 완전히 조회된 실시간 목록에서만 계산, 그것도 없으면 `미관측` | `Badge`, `StatusIndicator` |
| 운영 관제 보조 영역 | 노드·CPU·메모리를 미터로 표시(75% 경고·90% 위험, 값이 없으면 미관측). 원천 상태를 점+문구로 표시 | `Meter`, `StatusIndicator` |
| 장애 관제 | 운영자 결정이 필요한 장애가 있으면 목록 위에 바로가기 띠 표시. 빠른 필터를 `전체 · 대응 중(승인 대기/운영자 이관/분석 중) · 처리 결과(자동 복구/운영자 종료/처리 실패)`로 재구성. 결정이 필요한 행에 `승인·거절 필요`/`인수 필요` 표시 | — (토큰만) |
| 장애 관제실 | 결정이 필요한 상태에서는 "다음" 줄을 **"지금 할 일" 띠**로 강조하고 `승인 카드로 이동`/`인계 카드로 이동` 버튼으로 결정 카드까지 스크롤·포커스. 좁은 화면에서는 대화 탭으로 전환 | — (토큰만) |

안전 경계는 바꾸지 않았다: 승인·거절의 명시 확인, 계획 해시, 비밀값 입력, 인수가 변경 허가가 아니라는 안내는 기존 그대로다.

### 3.3 이번 범위에서 하지 않은 것

- 관제실 내부(단계 카드·상세 패널·명령 카드·실행 기록)를 디자인 시스템 컴포넌트(`ChatMessage`·`Composer`·`CodeBlock`·`DiagramNode` 등)로 교체하는 작업. 기존 단위·E2E 시험이 이 마크업에 묶여 있어 2차로 분리했다. 현재는 토큰으로 색·서체·곡률만 맞췄다.
- 검토 기록·설정 화면의 구조 변경(토큰만 적용).
- 다크 테마, 모바일 전용 재배치.

## 4. 완료 기준

- A1. `npm test`, `npm run build`가 통과한다.
- A2. 모의 API E2E(1440px)에서 리뉴얼 전 main에서 통과하던 시험이 리뉴얼 후에도 통과한다. 의도적으로 바꾼 계약(다이어그램 배경색)은 시험을 함께 고친다.
- A3. 운영 관제 첫 화면에서 스크롤 없이 "운영자 결정이 필요한 장애 수"와 "가장 먼저 볼 장애"를 읽을 수 있다.
- A4. 승인 대기·미인수 인계 장애는 알림, 운영 관제 대기열, 장애 목록에서 분석 중 장애보다 앞에 온다.
- A5. 관제실에서 결정이 필요한 상태면 한 번의 동작으로 결정 카드에 도달한다.
- A6. 값이 없는 집계는 0이 아니라 `미관측`으로 표시한다.
