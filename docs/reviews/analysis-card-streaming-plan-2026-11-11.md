> 💡 **요청** — K8s 관제의 분석 단계 카드에서 실행 중인 내용을 스트리밍으로 함께 확인한다. 사용자가 “진행 상황과 생성 중인 답변 모두 표시”를 선택했고, 이어 “작업 재개해”로 진행을 요청했다.

## 확인한 현재 상태

- `과제계획서.md`는 사건별 역할·모델 선택, 근거·판단·결과의 추적 가능성을 요구한다. 숨겨진 추론을 표시하는 요구로 해석하지 않는다.
- 실제 최신 소스와 현재 미리보기 빌드의 기준은 `/Users/hwany/sds-ai-professional`이다. 현재 채팅 작업 디렉터리의 제품 소스는 이전 버전이므로 그대로 수정해 덮어쓰지 않는다.
- `dashboard/src/StepCards.tsx`는 실행 중인 Agent에 고정 안내문만 표시한다. Agent 결론·후보·판정은 완료 결과에 의존한다.
- `liveprobe/app/engine.py`는 Agent 시작·완료를 `runlog`에 기록한다. `llm/codex_cli.py`는 프로세스 종료까지 `communicate()`로 기다린 뒤 출력 전체를 파싱한다. 현재 경로에는 답변 조각을 전달하는 계약이 없다.
- `IncidentRoom.tsx`는 실행 이벤트를 2초 간격으로 조회한다. 전역 SSE는 사건 변경 알림이며 분석 카드의 본문 스트림이 아니다.
- 기존 역할별 단계가 재시도·상위 모델 승격될 수 있으므로 역할 이름만으로 출력 조각을 합치면 서로 다른 시도의 답변이 섞일 수 있다.

## 제안 범위

1. 요청한 K8s 분석 카드 안에 실행 기록 영역을 추가한다. 실제 실행 단계, 대기·재시도·완료·실패와 제공자가 전달하는 공개 답변을 표시한다.
2. 생성 중인 답변을 포함하는 경우 제공자→실행 이벤트→카드까지 중간 출력을 전달한다. 전송을 지원하지 않는 제공자는 실제 진행 상태와 최종 결과를 표시하고, 지원 상태를 명확히 알린다. 글자 단위 출력이 없는 제공자에 가짜 글자 스트림을 만들지 않는다.
3. 사건·단계·호출/시도 식별자를 연결한다. 상위 모델 승격과 재시도 출력을 구별하고, 완성 전 출력에는 임시 표시를 붙인다. 최종 검증된 결론은 기존 결과 영역에 표시한다.
4. 순서 번호 기반 재연결·재조회와 중복 제거를 지원한다. 기존 로컬 접근 보호가 적용된 읽기 전용 경로로 전달하고, 스트림 단절 시 저장된 이벤트 조회로 복구한다. 목록 전체를 매 조각마다 다시 조회하지 않는다.
5. 카드 안의 기록은 접을 수 있게 한다. 입력 중인 지시·카드 선택·포커스·읽던 스크롤 위치를 유지하고, 출력 없음과 연결 끊김을 구별한다.
6. 현재 미리보기에 독립적인 스트리밍 표본을 추가해 실제 운영 기록과 구별한다. 소스·검증·로컬 미리보기까지 적용하며 운영 클러스터 갱신은 제외한다.

## 제약과 실패 처리

- 기존 DB, 테스트 기록, 완료 이력은 삭제하거나 재작성하지 않는다. 기존 이력에 없는 중간 출력은 새로 만들어 과거 사실처럼 표시하지 않는다.
- 스트림 전송·표시 실패가 모델 호출의 성공/실패나 조치 승인에 영향을 주지 않는다. DB 저장은 조각별 무제한 기록 대신 제한된 묶음으로 처리한다.
- 공개 답변과 실제 실행 상태만 전달한다. 제공자의 숨겨진 추론·인증 정보·원본 프롬프트·원본 CLI 진단 로그는 전달하지 않는다. 분할 경계에 걸친 민감값도 처리할 수 있도록 필터링한다.
- Application 제품의 실행·배포 소유권과 K8s 관제의 기존 분리는 유지한다. 이번 캡처에 없는 Application 화면 확대는 별도 요구로 다룬다.
- Jira는 사용하지 않으며 이 문서가 작업 범위와 검증 근거의 기준이다.

## 완료 기준과 검증 계획

- 모델이 끝나기 전에 카드에 실제로 전달된 진행/답변이 표시된다. 지원하지 않는 경로는 그 사실을 표시한다.
- 여러 사건·동일 역할의 재시도·상위 모델 승격 시 출력이 섞이지 않는다.
- 연결 단절·재연결·페이지 재방문 시 저장된 기록이 순서대로 복원되고 중복되지 않는다.
- 임시 답변이 실패하거나 검증을 통과하지 못하면 확정 결론처럼 표시되지 않는다.
- 민감 정보와 숨겨진 추론은 API/이벤트에 나타나지 않는다. 스트림 오류·타임아웃이 기존 실행 결과를 바꾸지 않는다.
- 브라우저에서 입력 유지·포커스·수동 스크롤·접기/펼치기·완료 전환을 확인한다.
- 제공자/이벤트 단위 격리 테스트, 카드 관련 브라우저 회귀 테스트, TypeScript 검사와 프로덕션 빌드 결과를 여기에 기록한다.

## 구현 계약과 실제 지원 수준

- `agent_started`와 `agent_finished`에 `call_id`를, `agent_progress`에 `attempt_id`를 추가했다. 단계 노드가 같은 호출을 가리키므로 동일 역할의 과거 호출과 재시도를 섞지 않는다.
- `/api/incidents/{iid}/events/stream`은 저장된 실행 이벤트를 순서대로 재생한다. 읽기 경로에서 모델 호출이나 DB 쓰기는 없다. 중간 답변마다 전체 사건 목록을 다시 불러오지 않는다.
- 카드에서 단계 진행, 호출별 공개 답변, 임시 응답 여부, 실패·재연결·저장 기록 상태를 표시한다. 실행 중의 빈 원인 후보/검증 판정 표는 숨기고 완료 결과에서 보여 준다.
- Codex CLI는 프로세스가 끝나기 전부터 JSONL 이벤트를 읽는다. 공개 `agent_message`만 표시 대상으로 삼으며 CLI가 메시지를 전달하는 시점에 갱신한다. 토큰 단위 스트림을 제공한다고 주장하지 않는다.
- OpenAI Responses는 지원 SDK에서 공개 텍스트 delta를 수신한다. 비밀값이 여러 조각에 걸쳐 유출되지 않도록 JSON의 공개 요약·판단 사유 문자열이 완성된 시점에 표시한다. 숨겨진 추론·도구 원문·CLI 오류 원문은 전달하지 않는다.
- Anthropic API/Claude CLI 및 스트림 미지원 SDK는 기존 완료 응답 경로를 유지하고 “완료 응답을 한 번에 전달” 상태를 표시한다. 모델·요금제·인증·제공자 폴백을 변경하지 않았다.
- 브라우저는 재연결 시 마지막 순서 번호부터 수신하고 저장 기록 조회로 보완한다. 스냅샷 500건 경계도 이어 읽는다. 구형 서버에는 기존 폴링으로 호환된다.
- 미리보기 하단의 **스트리밍 예시** 링크는 별도 합성 시험 사건을 생성한다. 도착하는 답변과 완료 전환을 메모리에서 재현하며 기존 시험 표본·DB를 수정하지 않는다. 실제 실행·배포 요청은 계속 차단된다.

공식 동작 확인에는 [Codex 비대화형 JSONL 출력 문서](https://learn.chatgpt.com/docs/non-interactive-mode?translationFallback=fr-FR)와 [Responses 스트리밍 문서](https://developers.openai.com/api/docs/guides/streaming-responses)를 참조했다. 사용자 선택 범위를 완료했으며 실제 운영 클러스터 배포는 이번 범위에 포함하지 않았다.


## 표시 경로 보완 — 사용자 캡처 피드백

사용자 캡처에서 실행 카드가 접혀 있었고 상세보기에는 스트리밍 영역이 없었다. 최초 구현의 표시 경로 누락을 확인하고 다음과 같이 보완했다.

- 실행 중인 분석·검증·분류 카드는 펼치지 않아도 실행 내용이 바로 표시된다.
- 상세보기 상단에도 같은 실행 기록과 답변을 연결했다. 별도 SSE 연결을 만들지 않고 관제실이 수신한 상태를 함께 사용한다.
- 상세보기를 열어 둔 동안 도착한 새 답변도 표시된다. 확정 결론 원문과 수신 중인 임시 답변을 구별한다.
- 정적인 미리보기 사례는 `execution_mode=snapshot`으로 표시한다. “저장 당시 실행 중”이라는 설명과 새 답변이 발생하지 않는 이유를 보여 주며 실제 실행처럼 안내하지 않는다. 기존 표본 내용은 바꾸지 않았다.
- 원본 저장소 소스·테스트 7개 파일에 해시 확인 후 적용했고 미리보기 서버도 갱신했다. DB·클러스터 변경은 없다.
