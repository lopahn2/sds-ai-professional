LiveProbe 동일 장애 출발점 재평가

2026년 11월 25일까지 보존된 원장과 실행 기록 재분석

결론사례 분류와 채택 기준채택한 이미지 실패 3건방식별 복구 시간과 비용근거 자료

결론

기존 dev에서 동일한 장애 상태, 같은 정상 상태로 돌아갈 수 있는 조치 범위, 동일한 복구 확인 기준이 확인된 시험은 이미지 가져오기 실패 3건, 다섯 방식의 실행 15회였다. 첫 비교에서 LiveProbe는 3건 중 2건, 단독 모델 네 종은 각각 3건을 조치로 복구했다. 다섯 방식이 모두 복구한 공통 2건에서 LiveProbe의 복구 시간 합은 가장 길었고, 모델 환산 비용은 Astra·Sol보다 낮았다. 사례 연결과 원본 지문 · 이미지 시험 기록

이 세 사례에서 LiveProbe는 Kubernetes 신호로 사건을 만들었고 단독 모델은 같은 이미지 오류를 시험기로부터 전달받았다. 따라서 결과는 동일하게 재현된 장애의 최초 관측부터 업무 복구까지 각 방식이 걸린 시간과 비용을 보여준다. 첫 모델 호출에 들어간 입력과 조회 도구까지 동일함을 증명할 기록은 0건이다. 모델 판단력만의 우열이나 전체 장애 유형의 성과는 이 자료로 확정할 수 없다. 오류 관측·입력·원복 실행기

사례 분류와 채택 기준

OOM을 제외한 원장에는 68개 사례·340개 실행이 있다. 각 사례에서 다섯 방식의 시험판 지문, 최초 오류의 비교 지문과 저장된 실행 기록의 SHA-256을 대조했다. 68개 모두 지문은 일치했다. 지문은 장애 재현이 일치했음을 확인하는 데 사용했고, 입력 전달 경로·조치 범위·시간과 종료 판정의 일치는 실행 코드와 영수증으로 별도 판정했다. 아래 표는 재집계 대상의 선정 근거이며, 채택한 세 건만 성과 표에 사용했다. 공식 원장 · 실행별 지문 목록

시험 종류사례 수채택 여부와 근거
기존 dev의 이미지 가져오기 실패3채택. F1-01, F1-07, F1-13. 같은 이미지 오류를 재현했고 각 방식이 원래 이미지로 원복할 수 있었다. 복구 확인에 같은 업무 요청을 사용했다.
기존 dev의 반복 종료·연결 풀·지연·짧은 연결 장애13제외. 다섯 방식의 서비스 정상화는 시험 설정의 만료로 관측됐다. 대응 방식이 실행한 복구의 시간과 비용을 직접 대조할 수 없다.
기존 dev의 Service 선택자 불일치4제외. F4-01, F4-03, F4-09, F4-11. LiveProbe는 고위험 이관 정책을 탔고 단독 모델에는 선택자 원복 도구가 열려 있었다.
신규 Kubernetes 인프라·버전 호환·워크로드 장애18제외. KI-01~KI-11, KW-01~KW-07. 별도 노드나 제어면을 사용한 시험을 포함한다. 배포 제품이 받는 신호와 단독 모델이 받는 최초 오류 또는 실행할 수 있는 조치의 동등성이 확인되지 않았다.
Application 설정 복원21제외. 단독 모델이 이용한 격리 시험기의 설정 원복 기능에 대응하는 LiveProbe 실행 경로가 없었다.
Application 소스 수정9제외. 같은 최초 오류 지문과 소스 기준선을 확인했으나, LiveProbe는 트레이스와 소스 판본을 묶어 접수하고 이미지 빌드·후보 확인까지 실행했다. 단독 모델은 최초 로그에서 도구 조회를 시작했고, 수정한 시험 프로세스의 복구를 확인했다. 입력과 측정 흐름이 다르다.

자연 회복 13건은 F1-04·06·12, F3-02·05·07·08·09·11·14, F4-02·08·12다. Application의 소스 수정 9건은 catalog-24, delivery-25·29, member-13·23, order-11·21, payment-12·22다. 제외한 결과는 원장에 그대로 남아 있다. 제외는 결과의 성공 여부와 무관하게 실험 조건으로 정했다. 자연 회복 판정 코드 · 선택자 장애 원기록 · 신규 유형 카탈로그 · Application 실행 대조 · Application 제품 실행기 · 단독 실행기

채택한 이미지 실패 3건

세 사례는 기존 dev의 재고·주문 Deployment에서 새 Pod의 이미지 가져오기 실패를 재현했다. 각 사례에서 기존 정상 Pod와 Service는 계속 업무 요청에 응답했다. 복구는 새 롤아웃이 정상 이미지와 준비 상태를 회복하고, 시험기의 정리 전에 독립 확인 두 차례를 통과했을 때 인정했다. LiveProbe는 rollout_undo, 단독 모델은 시험 도구의 이미지 필드 변경을 사용했으며 같은 버전으로 돌아갔다. 사용자 요청이 계속 실패하는 서비스 장애의 복구 시간으로 일반화할 수 없다. dev 기준선과 검증 · 실행기

방식별 복구 시간과 비용

복구 시간은 시험기가 첫 이미지 오류를 관측한 때부터 원래 배포가 준비되고 업무 확인을 마친 때까지다. LiveProbe의 wall_duration_ms − first_error_ms와 단독 실행의 first_error_to_verified_ms를 대조했다. 시간·토큰·비용은 다섯 방식이 모두 실제 복구한 `F1-07`, `F1-13` 두 건에서 계산했다. F1-01 LiveProbe 실행에는 확인된 복구 시각이 없어 이 표의 시간 집계에 넣지 않았다. 비용은 USD 모델 단가 환산액이며, 당시 구독 사용 요금과 구분된다. 시간 및 판정 집계 코드 · 공식 원장
