# LiveProbe 과제계획서 대비 평가

평가일: 2026-11-01. 요청 기준: `과제계획서.md` 1~197행 전체와 사용자가 지정한 세 질문.

## 결론

1. **주요 기능의 동작과 선택 이유를 확인할 수 있는 시스템은 구현돼 있다. 그러나 계획서의 모든 개선 효과가 입증된 시스템은 아니다.** 과거 4방식 실험과 재계산 가능한 지표 도구가 존재하지만, 비용·선택 정확도·복구 성공률 목표는 미달한 구간이 있고, 현재 삼성 3시스템·현재 모델 구성에 대한 같은 조건의 비교 결과는 이번 평가에서 확인하지 않았다.
2. **단계별 실행 근거는 상당 부분 남지만, 그 판단 방식이 최적이라는 실증 근거와는 다르다.** 수집 원문·분류 특징·점수·역할·모델·출력·검증·조치·이관 기록이 있다. 반면 수동 품질 점수·가중치, 자신이 보고한 신뢰도, 인용문과 원인 사이의 의미 관계에는 검증 공백이 있다.
3. **AI 기술 개선 여지는 크다. 우선순위는 에이전트 추가가 아니라 평가 계약 정합성, 근거 충분도에 따른 조기 종료, 역할별 실제 효용 측정, 의미 수준의 검증, 컨텍스트 선별이다.** 구조화 출력·인용 검증·역할별 승격·혼합 검색은 이미 있으므로 새로 도입해야 할 미구현 기술처럼 제안하면 안 된다.

이 평가는 별도 평가 화면을 추가하지 않고 문서로 남긴다. 새 장애 주입·모델 호출·종료 캠페인 재개를 하지 않았다. 권고사항은 구현 승인이나 새 작업 착수가 아니다.

## 1. 판정과 근거 범위

- 구현 확인: 소스 또는 실제 응답에서 기능과 기록을 확인했다.
- 부분 구현: 기능 일부는 있으나 계획서 문장 전체와 동일하지 않다.
- 과거 목표 미달: 과거 실험에서 해당 수치가 목표에 못 미쳤다.
- 현재 구성 미검증: 삼성 시스템·현재 모델·현재 정책에 대한 정량 결과를 이번에 확인하지 않았다. 실패라고도 성공이라고도 처리하지 않는다.
- 설계·실행 근거: 왜 그렇게 처리했는지 기록·추적할 수 있다는 뜻이다.
- 효과 입증 근거: 동일 조건 비교에서 품질·비용·안전 지표가 개선됐다는 뜻이다. 앞 항목만으로 뒤 항목을 입증하지 않는다.

현재 운영 사건 예시는 #1258이다. 과거 성능 자료는 P10~P13이고, 종료된 P18은 별개의 부분 캠페인이다. 이 셋을 합산해 현재 제품의 성능 수치로 만들지 않았다.

사건당 추정 비용은 A $0.064980, B $0.163498, C $0.235668이다. 모델·정책·시스템이 바뀐 현재 비용으로 사용하지 않는다.

**재현성에서 발견한 문제:** 기존 보고서를 현 지표 코드로 `verify`하면 A/B/C 모두 종료코드 1이다. 후속 대조에서 각 40개 집계의 숫자·분모·판정은 그대로이고, 바뀐 것은 `definitions_sha256`, 각 집계의 `export_digest`, 전체 `report_digest`임을 확인했다. 원본이 조작됐거나 수치가 틀렸다고 판정하지 않는다. 다만 현 코드와 과거 보고서가 같은 평가 계약으로 봉인돼 있지 않다는 실제 공백이다. 정의 버전은 여전히 `kan59-metrics/v1`인데 모델 클래스 표 등의 변경이 정의 지문에 반영된다. 과거 정의를 함께 보관하거나 정의 버전을 올리는 절차가 필요하다. 원본 보고서나 정답을 고쳐 통과시키지 않았다.

세 재계산 보고서는 모두 `publishable:false`다. 구간별 전체 60×4 쌍이 없고 미채점 영역이 있으므로, 한 구간의 부분집합 관측값을 전체 목표 달성으로 승격할 수 없다.

## 5. 권고 작업 목록 — 이번 요청에서는 평가만 수행

번호별로 별도 구현 범위와 검증 기준을 잡을 수 있게 분해했다. 아래는 새 실행 목록이 아니라 후속 의사결정용 권고다.

1. **평가 계약 정합성:** 과거 정의를 함께 보관하고 정의 변경 시 버전을 올린다. 검증은 같은 원장+정의가 같은 digest를 내고 다른 정의는 명시적으로 거부하는 오프라인 회귀다. 모델·클러스터 실행은 필요 없다.
2. **선택 정확도 계약 확장:** 수준 일치와 역할·모델·effort 일치, 최소비용 제약 충족을 별도 지표로 분리한다. 승인 라벨을 임의로 고치지 않는다. 정답 승인·채점기 회귀·누락 필드 unknown 처리가 완료 기준이다.
3. **근거 충분도·상태 해소 분기:** #1258처럼 현재 건강하지만 신호 직접 근거가 없는 사건을 대형 Group 전체 호출과 구분한다. 저장 스냅샷 회귀 후, 승인된 소수 읽기 전용 실제 사례로 확인하고 배포한다. 보호 대상·고위험 판정 하한을 낮추지 않는다.
4. **역할별 호출 효용과 모델 선택:** 챌린저·검증·요약을 각각 생략/저비용/기존 모델로 비교하는 오프라인 재생 설계를 만든다. 기존 결과를 원장에 남기고 새 호출을 할지는 사용자 결정이다. 성능이 유지되는지 확인 전 운영 매핑을 바꾸지 않는다.
5. **검증 강도 통일:** SIMPLE/HIGH_RISK에도 NORMAL/COMPLEX와 동일한 출처·인용 계약이 필요한지 먼저 합의한다. 형식 회귀·조작 인용/관련 없는 진짜 인용·반대 증거 시험을 구분하고 UI/API 배포 후 근거 연결을 확인한다.
6. **컨텍스트·검색 개선:** 역할별 중요 정보 보존, 한글 질의, 길이 초과, 시간순·반대 증거 누락 회귀를 먼저 고정한다. 검색 적중과 입력 토큰을 함께 측정하고 배포 후 실제 원문 연결을 확인한다.
7. **멱등 재개:** 읽기 분석 재개와 외부 쓰기 결과 재조회를 분리한다. 프로세스 중단 회귀에서 이미 실행한 조치가 중복되지 않아야 한다. 실제 장애 조작·재시작 시험은 현재 요청 범위 밖이므로 별도 승인 후 한다.

추가 권고: 3.4절의 저신뢰 최종 수용·미관측 사용량·실제 시도 횟수·검색 전달/인용 구분·최초 신호 보존·실행 입력 고정을 위 번호 1·2·5·6·7의 완료 기준에 포함한다. 새 비교 실행보다 앞서 오프라인 계약 회귀로 정합성을 확인할 항목이다.

별도 사용자 판단이 필요한 항목은 (a) 미달 수치에 대한 목표 유지/수정, (b) 현재 삼성 구성의 신규 비교 실험 수행 여부, (c) 후속 확장 기능의 우선순위다. 이번에는 미달을 감추기 위해 목표·정답·계획서를 수정하지 않았다.

## 6. UI 수정과 확인 위치

두 UI 결함의 수정·배포 기록은 `docs/evidence/dashboard-detail-fix/README.md`에 있다. 단위 130·모의 브라우저 48 통과와 실제 사건1258의 넓은/좁은 화면 확인은 UI 회귀 근거이지 AI 성능 수치가 아니다.

별도 조사 3개와 UI 검토 1개의 완료 상태를 확인하고 부모가 핵심 근거를 직접 대조했다. 이후 UI 검토의 전체 구조화 결과가 지연 도착해 `docs/evidence/dashboard-detail-fix/independent-review.json`에 보존했고, E2E를 포함한 대상 5개 파일의 전체 SHA가 현재 소스와 모두 일치함을 확인했다. UI 검토 판정은 통과이며 신규 보안·논리 결함은 없었다. 검토자는 상세 단위시험 24개만 직접 실행했으므로 부모의 전체시험·브라우저·배포 검증과 구분한다. 단계 전체 상세의 경계값 회귀·Group/해석 본문 검증·가림막 닫기 후 초점 단언 보강과 별도 접근성 개선 후보는 비차단 권고로 남겼고 추가 구현·재배포하지 않았다. UI 검토를 이 평가 보고서 전체나 AI 목표 달성의 독립 승인으로 확대하지 않는다. 새 API 키 사용·인증정보 열람·업무 리소스 변경·커밋·push는 하지 않았다.
