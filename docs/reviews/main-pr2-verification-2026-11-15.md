## 수정이 필요한 사항

### 1. 실제 호출·토큰·시간 집계가 누락됨

`dashboard/src/explainModel.ts:16`은 전체 AgentRun이 아닌 화면 흐름 노드로 합계를 구한다. 기존 flowgraph는 interpreter를 첫 1건만 넣고 반복문을 끝낸다(`liveprobe/app/flowgraph.py:168`). 따라서 여러 번 해석한 실제 사건에서는 새 사용량 요약이 부분 합계를 전체처럼 표시한다.

| 실제 사건 #1404 | 저장 기록 전체 | 새 화면 표시 |
|---|---:|---:|
| 모델 호출 | 8회 | 7회 |
| 입력 토큰 | 122,697 | 110,644 |
| 출력 토큰 | 5,676 | 5,392 |
| 응답 시간 합 | 174.018초 | 164.622초 |

누락된 실행은 interpreter #5997이다. 비용은 전체 실행을 사용하므로 같은 요약 안에서도 집계 범위가 다르다. 화면 노드와 별개로 저장 실행 전체를 집계해야 한다.

### 2. 정상 수집된 코드 근거를 미수집으로 경고함

`liveprobe/app/flowgraph.py:433`의 `source_labels`가 화면용 `routing_ko.SOURCE_REF`를 재사용한다. 이 맵은 `code_refs: None`이므로 모델이 실제로 사용하는 `E8_code_refs`를 등록하지 않는다.

#1404에는 성공한 code_refs 수집 행 4개가 있는데, 분석 카드 5개 모두 해당 인용을 ‘수집되지 않은 근거 번호’로 경고한다. 검증 카드에서 실제로 ‘인용 3건 · 확인되는 출처 2건’과 잘못된 경고가 표시되는 것을 확인했다. 모델에 제공한 근거 ID와 일치하는 맵을 사용해야 한다.

추가로 같은 함수의 `ref_known`은 문서 인용이 하나만 저장돼 있어도 존재 여부를 확인할 수 없는 `R999`를 true로 만든다(`flowgraph.py:467`). 구체적인 R 번호와 문서의 연결이 저장되지 않았다면 ‘연결 미확인’으로 구분해야 한다. 인용문 원문 일치 검증과는 별개의 출처 연결 문제다.

### 3. ‘로그 원문만 접기’ 합의가 main에 아직 통합되지 않음

이 세션의 `codex/visible-incident-summaries` / `3becacb`와 PR #2는 같은 부모 `2146f44`에서 갈라진 변경이다. main은 해당 브랜치를 포함하지 않는다.

- `IncidentRoom.tsx:271`: 지난 분석 단계 전체를 접는다.
- `StepCards.tsx:104`: 카드 본문 전체를 열었을 때만 표시한다.
- 실제 #1404에서 첫 화면에 원인 요약이 없고, 과거 분석 목록과 원인 후보·검증 결과가 접혀 있다.
- 실제 4건의 반대 근거는 한글 해석이 모두 없어 내용이 ‘반대 근거 원문 보기’ 뒤에만 있다. 새 모의 fixture의 한글 반대 근거처럼 기본 노출되지 않는다.

이는 PR의 역할별 모델 배치 추가와 별도로, 두 작업을 합쳐야 하는 통합 과제다. 기존 DB를 다시 쓰거나 이력을 지울 필요는 없다.

## 실제 기록 검증 방법

운영 API Pod에서 별도 Python 프로세스를 실행해 main의 flowgraph 코드만 메모리에 로드했다. `REPEATABLE READ` + `SET TRANSACTION READ ONLY` 연결로 저장된 4건에 대해 build_narrative를 수행했다. 모델이나 워커는 시작하지 않았다. 저장된 agent_runs 5,967건 / actions 111건 / incidents 1,373건을 읽었고 해당 트랜잭션 내 전후 개수는 같았다. 운영 API 프로세스와 파일은 변경하지 않았다.

그 응답을 main 빌드의 별도 읽기 전용 화면에 연결하여 #1404의 호출 집계·후보·인용·반대 근거·검증 판정을 확인했다. 모든 변경 요청은 차단했다. 실제 #971·976에는 참고 문서 인용과 승격 기록도 포함돼 새 필드가 생성되는 것을 확인했다. 이 검수는 실제 기록 열람이며 신규 장애나 신규 AI 실행 시험은 아니다.
