시험 범위와 판정

전체 캠페인의 진행 현황은 355/375회 완료였다. 이 보고서의 비교 범위는 68개 시나리오 × 5개 방식 = 340회다. 기본 20개, 신규 Kubernetes 18개, Application 30개를 포함한다. 커널 OOMKilled 주입이 시험 조건인 F2-01, F2-03, F2-05, F2-07, F2-10, F2-13, F2-15를 제외했다. 제외한 35회는 완료 15회와 미실행 20회다. Application의 delivery-09, delivery-29, notification-20은 격리 서비스의 메모리 증가·업무 오류를 검증한 사례로 포함했다. 선정 카탈로그 · 커널 OOM 정의 · Application 메모리 관측

단독 모델은 최초 오류 로그와 조사·복구 요청으로 시작하고, 이후 필요한 자료를 시험 도구로 조회했다. LiveProbe는 시험별 수집·분류·분석·조치 절차를 사용했다. 포함한 68개 사례 모두에서 다섯 방식의 초기 입력 지문이 일치했다. 비교에는 dev 실워크로드, 별도 Kubernetes 시험 클러스터, 격리 Application 시험 환경이 들어 있다. 시험 프로토콜 · 원본 영수증 대조

  • 조치 후 복구는 해당 방식이 적용한 조치에 이어 독립 업무 확인 또는 리소스 확인을 통과한 기록이다.
  • 자연 회복은 장애 만료 등으로 정상 응답을 다시 확인한 기록이다. 자동 복구 건수에는 합산하지 않았다.
  • 분석 후 미복구는 대응이 실행됐고 관측 구간 내 조치 후 복구를 확인하지 못한 기록이다. 미감지·장애 지속은 시험기가 장애 지속을 확인했으나 LiveProbe 사건이 생성되지 않아 분석이 실행되지 않은 경우다. 이 경우는 분석 후 미복구와 구분하며 비용을 0으로 대체하지 않았다. 판정 코드
