| 대상 | 장애 유형과 실제 주입 | 복구 후보 | 필수 관측 |
|---|---|---|---|
| lp-memory | 정상 작업 집합보다 컨테이너 메모리 한도 축소 | 제한 내 메모리 증설 | 새 OOMKilled, 낮아진 한도, 새 파드 정상 |

수정은 다음 새 시도부터 적용한다. CPU/메모리의 실제 Prometheus 값을 전달하며 현재 Pod 이름만 모델 보기로 제한한다. 컨테이너 지표가 없는 런타임은 Pod 합계 지표를 선택하고 둘을 중복 합산하지 않는다. 미관측은 0으로 채우지 않으며 비정상 sample은 원문 없이 분리한다. Deployment 근거에는 저장소 종류·마운트·Pod 교체 시 유지 여부를 추가하며 Secret/PVC 참조명·hostPath 원본 경로는 전달하지 않는다. hostPath는 노드 변경 가능성 때문에 유지 여부를 확정하지 않는다.

시험 컨테이너 v2는 HTTP 프로세스를 PID 1의 자식으로 한 번 실행하고 기다리며 자동 재시작·원복을 하지 않는다. 변경 대상은 lp-storage/lp-process뿐이다. digest로 고정한 격리 컨테이너에서 PID>1·정지 상태 T·ENOSPC·공간 0과 경량 관측 일치를 확인했다. 첫 태그 기반 검사 증거도 보존했다. PID 네임스페이스 초기 프로세스의 신호 제한은 [Linux man-pages](https://www.man7.org/linux/man-pages/man7/pid_namespaces.7.html)를 확인했다.
