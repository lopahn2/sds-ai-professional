## 독립 검토 반영

`local-k8s-dashboard-iteration/SKILL.md`의 실행 권한 확대 전 독립 검토 요구에 따라 읽기 전용 검토를 받았다.

- NORMAL/COMPLEX 자동 조치는 이미 구현돼 있다. engine의 “항상 이관” 주석만 보고 새 실행 통로를 중복 추가하지 않는다.
- 승인된 제안은 engine.py→proposals.py→safety.py 경로로 실행된다. 모델·근거·정책·출처·검증 실패를 분류한 뒤 불필요한 최초 실패 이관을 줄인다.
- stg 삭제가 과거 검색/CSV와 Application 승격의 하드코딩을 깨뜨리지 않도록 활성 환경과 이력 환경을 분리한다.
- 설계상 복잡 장애와 실제 라우팅 결과를 구별하고, 시험 도구의 clear/restart나 TTL 만료를 AI 복구 성공으로 세지 않는다.

## 운영자 이관 두 경계

1. **권한·데이터 안전 경계:** 허용 범위 밖 변경, 데이터 손실 위험, 소스 출처 미확인, 인증/권한 제공 필요, 이미 시작한 쓰기의 결과가 불명확한 경우.
2. **제한된 자율 복구 소진:** 재수집·다른 역할/상위 모델·수정·재시험·검증/안전한 보상을 수행했지만 정해진 횟수·비용·시간 안에서 안전한 복구를 증명하지 못한 경우.

일시 수집 실패, 한 번의 잘못된 모델 출력, 최초 저신뢰·반론은 가능한 범위의 재시도로 처리한다. 세부 원인·실패·시도·비용·검증 결과는 모두 기록한다. 이관을 성공 상태로 덮거나 보안·독립 검증 문턱을 없애지 않는다. prd 배포 승인은 사건 이관과 별도이며 기존 승인 경계를 유지한다.

## dev/prd 전환과 보존

- 신규 실행·감시·카탈로그·UI·RBAC·렌더러의 활성 환경은 dev/prd다.
- 신규 Application release는 버전된 **dev 수정/시험/배포/업무 검증→dev 사용자 시험→prd 계획·승인→동일 digest 배포/검증** 경로로 전환한다.
- 기존 stg release·사건·승인 지문은 변경하지 않는다. 과거 규약을 표시하고 퇴역 환경으로 새 쓰기를 배정하지 않는다.
- stg Deployment·Service·Ingress·불필요한 실행 바인딩을 이름·UID·RV와 소유권을 확인해 개별 퇴역시킨다. 전체 overlay 적용, namespace 일괄 삭제, PVC/PV/DB/기존 Secret 삭제는 하지 않는다.
- `stg` namespace는 보존 중인 Secret·정책·이력 참조를 위해 퇴역 상태로 남길 수 있다. 활성 환경 수는 2개다.
- 메모리 5개 서비스의 조회 가능한 데이터는 제한된 보호 경로에 export하고 수량·내용 지문·한계를 기록한다. 완전 export/freeze가 증명되지 않으면 원본 Pod 종료를 보존 성공으로 간주하지 않는다. 메모리 시험 데이터 정리 예외 여부는 별도 확인한다.
